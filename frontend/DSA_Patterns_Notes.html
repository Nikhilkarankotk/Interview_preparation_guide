Two Pointers

Sub-Pattern 1: Opposite Ends (Converging)

💡 Core Concept

We use two references (indices) starting at opposite ends of the array. They move toward each other based on a specific condition.
Requirement: The array MUST be sorted (or monotonic) to know which pointer to move. This reduces O(N²) brute force to O(N).

🧠 Step-by-Step Intuition

Imagine finding a pair that sums to a target in a sorted array.

  • Initialize left = 0, right = N-1.
  • Calculate sum.
  • If sum is too small: The only way to increase the sum is to move left forward (to a larger number).
  • If sum is too large: The only way to decrease the sum is to move right backward (to a smaller number).

📝 Java Implementation

public int[] twoSum(int[] numbers, int target) {
    int left = 0;
    int right = numbers.length - 1;
    
    while (left < right) {
        int sum = numbers[left] + numbers[right];
        
        if (sum == target) {
            return new int[]{left + 1, right + 1};
        } else if (sum < target) {
            left++;  // Need larger sum
        } else {
            right--; // Need smaller sum
        }
    }
    return new int[]{-1, -1};
}

⏱️ Complexity

Time: O(N). We visit each element at most once.

Space: O(1).

💡 Other Uses: Valid Palindrome, Container With Most Water.

Sub-Pattern 2: Same Direction (Fast & Slow)

💡 Core Concept

Both pointers start at the beginning. The fast pointer explores ahead, while the slow pointer stays behind to overwrite elements. Used heavily for in-place array modification (no extra space).

🧠 Step-by-Step Intuition

Think of fast as the "Read" pointer and slow as the "Write" pointer.

  • Move fast every step.
  • Only move slow when you find a valid element that needs to be kept.
  • Copy nums[fast] to nums[slow].

public int removeDuplicates(int[] nums) {
    if (nums.length == 0) return 0;
    int slow = 0;
    
    for (int fast = 1; fast < nums.length; fast++) {
        if (nums[fast] != nums[slow]) {
            slow++;
            nums[slow] = nums[fast];
        }
    }
    return slow + 1;
}

⏱️ Complexity

Time: O(N). Single pass.

Space: O(1).

💡 Other Uses: Move Zeroes (keep non-zeros at slow, fill rest with 0).

Sub-Pattern 3: Dutch National Flag (3-Way Partition)

💡 Core Concept

Used when you need to partition an array into three distinct groups in a single pass (e.g., sort 0s, 1s, 2s). It uses Three Pointers: low, mid, and high.

🧠 Step-by-Step Intuition

  • low tracks the boundary of 0s.
  • high tracks the boundary of 2s.
  • mid explores the unknown region.
  • If nums[mid] == 0: Swap with low. `low++`, `mid++` (we know the swapped element is 1).
  • If nums[mid] == 1: It's in the right place. `mid++`.
  • If nums[mid] == 2: Swap with high. `high--`. DO NOT increment mid (the element from high is unknown).

📝 Java Implementation

public void sortColors(int[] nums) {
    int low = 0, mid = 0;
    int high = nums.length - 1;
    
    while (mid <= high) {
        if (nums[mid] == 0) {
            swap(nums, low, mid);
            low++; mid++;
        } else if (nums[mid] == 1) {
            mid++;
        } else {
            swap(nums, mid, high);
            high--;
        }
    }
}

⚠️ Pitfall

Never do `mid++` when swapping with `high`! The new value at `mid` came from the end and has not been checked yet.

Sub-Pattern 4: Multi-Pointer (3Sum)

💡 Core Concept

Fixing one pointer and applying the Opposite Ends pattern on the remaining array. Used for finding triplets (3Sum) or quadruplets (4Sum) that sum to a target.

🧠 Step-by-Step Intuition

  • Step 1: Sort the array. This allows us to skip duplicates and use Two Pointers.
  • Step 2: Iterate `i` from 0 to N-3.
  • Step 3: Skip duplicate `i` values.
  • Step 4: Set `left = i + 1`, `right = N - 1`.
  • Step 5: Use standard Opposite Ends logic to find `nums[i] + nums[left] + nums[right] == 0`.
  • Step 6: When a valid triplet is found, skip duplicates for `left` and `right` before moving them.

public List<List<Integer>> threeSum(int[] nums) {
    Arrays.sort(nums); // Crucial
    List<List<Integer>> res = new ArrayList<>();
    
    for (int i = 0; i < nums.length - 2; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue; // Skip dup i
        
        int left = i + 1, right = nums.length - 1;
        while (left < right) {
            int sum = nums[i] + nums[left] + nums[right];
            if (sum == 0) {
                res.add(Arrays.asList(nums[i], nums[left], nums[right]));
                while (left < right && nums[left] == nums[left + 1]) left++;
                while (left < right && nums[right] == nums[right - 1]) right--;
                left++; right--;
            } else if (sum < 0) left++;
            else right--;
        }
    }
    return res;
}

Forgetting `Arrays.sort(nums)` in 3Sum causes the pointers to move in the wrong direction, producing wrong results.

In 3Sum, if you don't skip duplicate `i`, `left`, and `right`, you will add duplicate triplets to the result list.

Sliding Window

Sub-Pattern 1: Fixed Size Window

💡 Core Concept

The window size is exactly K. It does not grow or shrink. Instead, it "slides" by adding the new element on the right and removing the oldest element on the left. This avoids recalculating the entire sum/window from scratch.

🧠 Step-by-Step Intuition

  • Step 1: Calculate the sum of the first K elements.
  • Step 2: Iterate from index K to the end.
  • Step 3: Add the current element (expand right).
  • Step 4: Subtract the element leaving the window (right - k).
  • Step 5: Update the maximum/minimum result.

📝 Java Implementation

public int maxSumFixed(int[] nums, int k) {
    int currentSum = 0;
    int maxSum = 0;
    
    // 1. Build initial window
    for (int i = 0; i < k; i++) {
        currentSum += nums[i];
    }
    maxSum = currentSum;
    
    // 2. Slide the window
    for (int right = k; right < nums.length; right++) {
        currentSum += nums[right];       // Add new
        currentSum -= nums[right - k];   // Remove old
        maxSum = Math.max(maxSum, currentSum);
    }
    return maxSum;
}

⏱️ Complexity

Time: O(N). Initial O(K) + Slide O(N-K) = O(N).

Space: O(1).

💡 No While Loop: Because the window size is fixed, we never shrink. We just slide.

Sub-Pattern 2: Variable Window (Longest)

💡 Core Concept

We want to find the longest valid window. Expand the window as much as possible. Only when the window becomes invalid do we shrink it from the left until it becomes valid again.
Golden Rule: while (window is INVALID) shrink();

🧠 Step-by-Step Intuition

  • Step 1: Expand `right` to include a new element.
  • Step 2: Check if the window is still valid.
  • Step 3: If invalid, increment `left` and remove `nums[left]` from state until valid again.
  • Step 4: Once valid, update the `maxLength`.

public int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> map = new HashMap<>();
    int left = 0, maxLen = 0;
    
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        map.put(c, map.getOrDefault(c, 0) + 1);
        
        // Shrink while invalid (duplicate exists)
        while (map.get(c) > 1) {
            char leftChar = s.charAt(left);
            map.put(leftChar, map.get(leftChar) - 1);
            left++;
        }
        maxLen = Math.max(maxLen, right - left + 1);
    }
    return maxLen;
}

Sub-Pattern 3: Variable Window (Shortest)

💡 Core Concept

We want to find the smallest valid window. Expand until valid. Then aggressively shrink while it remains valid to find the minimum possible length.
Golden Rule: while (window is VALID) shrink();

🧠 Step-by-Step Intuition

📝 Java Implementation

public int minSubArrayLen(int target, int[] nums) {
    int left = 0, sum = 0;
    int minLen = Integer.MAX_VALUE;
    
    for (int right = 0; right < nums.length; right++) {
        sum += nums[right];
        
        // Shrink while VALID (sum >= target)
        while (sum >= target) {
            minLen = Math.min(minLen, right - left + 1);
            sum -= nums[left];
            left++;
        }
    }
    return minLen == Integer.MAX_VALUE ? 0 : minLen;
}

Sub-Pattern 4: Monotonic Deque

💡 Core Concept

Used to find the Maximum/Minimum in a sliding window in O(1) time. We use a Deque (double-ended queue) to store indices in decreasing order (for max). The front of the deque is ALWAYS the maximum.

🧠 Step-by-Step Intuition

  • Step 1: Check if the front index is out of the current window (`i - k`). If so, pop from front.
  • Step 2: While the deque is not empty and the new value is greater than the value at the back of the deque, pop from back. (Maintains decreasing order).
  • Step 3: Push the current index to the back of the deque.
  • Step 4: If the window size is reached, record the value at the front.

📝 Java Implementation

public int[] maxSlidingWindow(int[] nums, int k) {
    Deque<Integer> dq = new ArrayDeque<>();
    int[] result = new int[nums.length - k + 1];
    
    for (int i = 0; i < nums.length; i++) {
        // 1. Remove out of bounds indices
        if (!dq.isEmpty() && dq.peekFirst() == i - k) 
            dq.pollFirst();
            
        // 2. Maintain decreasing order
        while (!dq.isEmpty() && nums[dq.peekLast()] < nums[i])
            dq.pollLast();
            
        dq.offerLast(i);
        
        // 3. Record result
        if (i >= k - 1) 
            result[i - k + 1] = nums[dq.peekFirst()];
    }
    return result;
}

Fast & Slow Pointers

Sub-Pattern 1: Cycle Detection (Linked List Cycle)

💡 Core Concept

Also known as Floyd's Tortoise and Hare. We use two pointers moving at different speeds. The slow pointer moves 1 step, the fast pointer moves 2 steps. If a cycle exists, the fast pointer will eventually lap the slow pointer and they will meet.

🧠 Step-by-Step Intuition

  • Initialize both pointers at the `head`.
  • Move slow by 1 step, fast by 2 steps.
  • If there is NO cycle: The `fast` pointer will hit `null` (end of list). We return `false`.
  • If there IS a cycle: Imagine a circular track. The fast runner will inevitably catch the slow runner from behind.
  • Condition: If slow == fast, a cycle is detected.

👀 Visual Dry Run

List: 1 -> 2 -> 3 -> 4 -> 5 -> 6 -> (back to 3)

Init:
Slow = 1, Fast = 1.
Step 1:
Slow moves to 2. Fast moves to 3.
Step 2:
Slow moves to 3. Fast moves to 5.
Step 3:
Slow moves to 4. Fast moves to 3.
Step 4:
Slow moves to 5. Fast moves to 5. Match!

📝 Java Implementation

public boolean hasCycle(ListNode head) {
    if (head == null) return false;
    
    ListNode slow = head;
    ListNode fast = head;
    
    // Fast needs to check both itself and fast.next
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        
        if (slow == fast) {
            return true;
        }
    }
    return false;
}

⏱️ Complexity

Time: O(N). In a cycle of length K, fast catches slow in at most K steps.

Space: O(1).

💡 Note: We check fast != null and fast.next != null to avoid NullPointerExceptions.

Sub-Pattern 2: Finding the Middle

💡 Core Concept

When the fast pointer reaches the end of the list, the slow pointer will be exactly at the middle.
Math: If Fast travels distance D, Slow travels D/2.

🧠 Step-by-Step Intuition

  • Odd Length: For [1, 2, 3, 4, 5], Fast stops at 5. Slow stops at 3 (exact middle).
  • Even Length: For [1, 2, 3, 4], Fast stops at `null` (after 4). Slow stops at 3 (the second middle).

public ListNode findMiddle(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;
    
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    
    return slow;
}

Sub-Pattern 3: Finding the Cycle Start

💡 Core Concept

Once the fast and slow pointers meet, we reset one pointer back to the head. Then, we move both pointers one step at a time. The point where they meet again is the start of the cycle.

🧠 Step-by-Step Intuition & Math Proof

Let x = distance from head to cycle start. Let y = distance from cycle start to meeting point. Let z = distance from meeting point to cycle start (rest of the cycle).

  • Slow traveled: x + y
  • Fast traveled: x + y + n(y + z) (where n is number of extra loops)
  • Since Fast is 2x: 2(x + y) = x + y + n(y + z)
  • Simplify: x + y = n(y + z) → x = (n - 1)(y + z) + z
  • Conclusion: Distance from head to start (x) is equal to distance from meeting point to start (z), plus some full loops. So, one pointer at `head` and one at `meeting point`, moving 1 step each, will meet at the cycle start!

📝 Java Implementation

public ListNode detectCycle(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;
    
    // Phase 1: Detect if a cycle exists
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) break;
    }
    
    // No cycle
    if (fast == null || fast.next == null) return null;
    
    // Phase 2: Find the start
    slow = head;
    while (slow != fast) {
        slow = slow.next;
        fast = fast.next; // Move both at 1x speed
    }
    
    return slow;
}

Sub-Pattern 4: Palindrome Linked List

💡 Core Concept

A palindrome reads the same forwards and backwards. For a linked list, this is solved by combining Finding the Middle and Reversing a Linked List. Once we find the middle, we reverse the second half and compare it with the first half.

🧠 Step-by-Step Intuition

  • Step 1: Find the middle of the linked list using Fast & Slow pointers.
  • Step 2: Reverse the second half of the list.
  • Step 3: Compare the first half with the reversed second half. If they match entirely, it's a palindrome.
  • Step 4 (Optional but good): Reverse the second half back to restore the original list.

👀 Visual Dry Run

Reverse:
Reverse from index 2 to end: [1, 2, 1, 2].
Compare:

📝 Java Implementation

public boolean isPalindrome(ListNode head) {
    if (head == null || head.next == null) return true;
    
    // 1. Find middle
    ListNode slow = head, fast = head;
    while (fast.next != null && fast.next.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    
    // 2. Reverse second half
    ListNode secondHalf = reverseList(slow.next);
    ListNode firstHalf = head;
    
    // 3. Compare
    while (secondHalf != null) {
        if (firstHalf.val != secondHalf.val) return false;
        firstHalf = firstHalf.next;
        secondHalf = secondHalf.next;
    }
    return true;
}

private ListNode reverseList(ListNode head) {
    ListNode prev = null;
    while (head != null) {
        ListNode nextTemp = head.next;
        head.next = prev;
        prev = head;
        head = nextTemp;
    }
    return prev;
}

Sub-Pattern 1: Standard Exact Match

💡 Core Concept

A divide-and-conquer algorithm that halves the search space at every step. Requirement: The search space must be monotonic (sorted). It reduces time complexity from O(N) to O(log N).

🧠 Step-by-Step Intuition

  • Initialize left = 0, right = N - 1.
  • Find the middle element: mid = left + (right - left) / 2.
    (This formula prevents integer overflow in Java/C++).
  • If nums[mid] == target, we found it!
  • If nums[mid] < target, the target must be in the right half. Move left = mid + 1.
  • If nums[mid] > target, the target must be in the left half. Move right = mid - 1.
  • Repeat until left > right (search space exhausted).

public int search(int[] nums, int target) {
    int left = 0;
    int right = nums.length - 1;

            return mid;

        } else {
            right = mid - 1; // Search left
        }
    }
    return -1;

Sub-Pattern 4: Binary Search on Answer

💡 Core Concept

Instead of searching an array, we search a range of possible answers [min_answer, max_answer]. We write a boolean function isValid(guess). If isValid(mid) is true, we try a smaller answer; if false, we try a larger answer.

🧠 Step-by-Step Intuition

  • If valid, record the answer and shrink the search space to the left (right = mid - 1) to find a potentially smaller answer.

public int minEatingSpeed(int[] piles, int h) {
    int left = 1;
    int right = 0;
    for (int pile : piles) right = Math.max(right, pile);
    
    while (left < right) {
        int mid = left + (right - left) / 2;
        
        if (canFinish(piles, mid, h)) {
            right = mid; // Try smaller speed
        } else {
            left = mid + 1; // Need larger speed
        }
    }
    return left;
}

private boolean canFinish(int[] piles, int speed, int h) {
    int hours = 0;
    for (int pile : piles) {
        hours += pile / speed;
        if (pile % speed != 0) hours++;
    }
    return hours <= h;
}

Sub-Pattern 1: 1D Range Sum Query

💡 Core Concept

Precomputing the cumulative sum of an array to answer multiple range sum queries in O(1) time.
Formula: prefix[i] = arr[0] + arr[1] + ... + arr[i].
Query: sum(L to R) = prefix[R] - prefix[L-1].

🧠 Step-by-Step Intuition

  • We create a new array prefix of size N + 1.
  • prefix[0] = 0. This acts as a dummy node to avoid edge cases when L=0 (because L-1 would be out of bounds).
  • We iterate through the original array: prefix[i+1] = prefix[i] + nums[i].
  • To find the sum from index L to R:
    prefix[R + 1] - prefix[L].

class NumArray {
    private int[] prefix;

    public NumArray(int[] nums) {
        // N+1 to handle L=0 gracefully
        prefix = new int[nums.length + 1];
        
        for (int i = 0; i < nums.length; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }
    }

    public int sumRange(int left, int right) {
        return prefix[right + 1] - prefix[left];
    }
}

Sub-Pattern 2: Subarray Sum Equals K (Prefix + HashMap)

💡 Core Concept

Find the number of subarrays that sum to exactly K. This is used when the array contains negative numbers (where Sliding Window fails).
Logic: If currentPrefixSum - K exists in our HashMap, then the subarray between that previous prefix and the current index sums to K.

🧠 Step-by-Step Intuition

  • Use a HashMap to store the frequency of prefix sums encountered so far.
  • Critical Initialization: map.put(0, 1). This represents the empty prefix sum, allowing subarrays starting from index 0 to be counted.
  • Iterate through the array, updating sum += nums[i].
  • Check if sum - K exists in the map. If yes, add its frequency to the count.
  • Add the current sum to the map (increment its frequency).

public int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> map = new HashMap<>();
    // Base case: sum 0 occurs once (empty subarray)
    map.put(0, 1);
    
    int count = 0, sum = 0;
    
    for (int num : nums) {
        sum += num;
        
        // Check if removing K leaves a known prefix
        if (map.containsKey(sum - k)) {
            count += map.get(sum - k);
        }
        
        // Store current prefix sum frequency
        map.put(sum, map.getOrDefault(sum, 0) + 1);
    }
    return count;
}

⏱️ Complexity

Time: O(N). Single pass, HashMap ops are O(1).

Space: O(N). Map stores up to N distinct prefix sums.

💡 Pro Tip: Do NOT forget map.put(0, 1). Without it, you will miss all valid subarrays starting from index 0.

Sub-Pattern 3: 2D Prefix Sum (Matrix Range Query)

💡 Core Concept

Used to find the sum of any sub-rectangle in a 2D matrix in O(1) time after O(M*N) precomputation. It uses the principle of Inclusion-Exclusion.

🧠 Step-by-Step Intuition

  • Build Formula:
    prefix[i][j] = matrix[i-1][j-1] + prefix[i-1][j] + prefix[i][j-1] - prefix[i-1][j-1].
    (We subtract the top-left because it was added twice).
  • Query Formula (r1,c1 to r2,c2):
    Sum = prefix[r2+1][c2+1] - prefix[r1][c2+1] - prefix[r2+1][c1] + prefix[r1][c1].
  • The extra row and column of zeros at the top and left of the prefix matrix handle boundary conditions automatically.

class NumMatrix {
    private int[][] prefix;
    
    public NumMatrix(int[][] matrix) {
        int m = matrix.length, n = matrix[0].length;
        // +1 to avoid out of bounds in the formula
        prefix = new int[m + 1][n + 1];
        
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                prefix[i][j] = matrix[i-1][j-1] 
                             + prefix[i-1][j] 
                             + prefix[i][j-1] 
                             - prefix[i-1][j-1];
            }
        }
    }

        return prefix[r2+1][c2+1] - prefix[r1][c2+1] 
             - prefix[r2+1][c1] + prefix[r1][c1];
    }
}

Sub-Pattern 4: Difference Array (Range Update)

💡 Core Concept

While Prefix Sum answers range queries quickly, the Difference Array performs range updates quickly. If we want to add `val` to every element in range `[L, R]`, we can do it in O(1) time.

public int[] getModifiedArray(int length, int[][] updates) {
    int[] diff = new int[length + 1];
    
    // 1. Apply all updates in O(1) time
    for (int[] update : updates) {
        int start = update[0];
        int end = update[1];
        int val = update[2];
        
        diff[start] += val;
        diff[end + 1] -= val;

    int[] result = new int[length];
    int currentSum = 0;
    
    for (int i = 0; i < length; i++) {
        currentSum += diff[i];
        result[i] = currentSum;
    }
    
    return result;
}

💡 Core Concept

Using a Hash Map (or a fixed-size array if the range is small, like lowercase English letters) to store the frequency of elements. This allows O(1) lookups for how many times an element has appeared.

public boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;
    
    // Array is faster than HashMap for fixed ASCII
    int[] count = new int[26];
    
    for (int i = 0; i < s.length(); i++) {
        count[s.charAt(i) - 'a']++;
        count[t.charAt(i) - 'a']--;
    }
    
    for (int c : count) {
        if (c != 0) return false;
    }
    return true;
}

public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> map = new HashMap<>();
    
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        
        if (map.containsKey(complement)) {
            return new int[]{map.get(complement), i};
        }

Sub-Pattern 4: Hash Set for Existence / Sequence

💡 Core Concept

Using a HashSet to check if an element exists in O(1) time. Extremely powerful for finding sequences (like Longest Consecutive Sequence) or checking for duplicates.

🧠 Step-by-Step Intuition (Longest Consecutive Sequence)

  • Add all numbers to a HashSet.
  • Iterate through the set. For each number num, check if num - 1 exists.
  • If num - 1 does NOT exist: This means num is the start of a sequence. Start counting upwards (num + 1, num + 2...) to find the length.
  • If num - 1 DOES exist, skip it. It's not the start, and we will count it later when we reach the actual start.

📝 Java Implementation

public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int num : nums) set.add(num);
    
    int longest = 0;
    
    for (int num : set) {
        // Only start counting if it's the beginning of a sequence
        if (!set.contains(num - 1)) {
            int currentNum = num;
            int currentStreak = 1;
            
            while (set.contains(currentNum + 1)) {
                currentNum++;
                currentStreak++;
            }
            longest = Math.max(longest, currentStreak);
        }
    }
    return longest;
}

⏱️ Complexity

Sub-Pattern 1: Standard Stack (Parentheses Matching)

💡 Core Concept

A Stack operates on a LIFO (Last-In-First-Out) principle. The most recently added element is the first one to be removed. It is used for validating nested structures (like brackets) or keeping track of the most recent state.

🧠 Step-by-Step Intuition

  • Iterate through the string.
  • If it's an opening bracket ((, [, {), push it onto the stack.
  • If it's a closing bracket, check the top of the stack.
    • If the stack is empty, it's invalid (no matching opening).
    • If the top matches the closing bracket, pop it.
    • If it doesn't match, it's invalid.
  • At the end, if the stack is completely empty, all brackets were matched correctly.

public boolean isValid(String s) {
    // Deque is preferred over legacy Stack in Java
    Deque<Character> stack = new ArrayDeque<>();
    
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '[' || c == '{') {
            stack.push(c);
        } else {
            if (stack.isEmpty()) return false;
            
            char top = stack.pop();
            if (c == ')' && top != '(') return false;
            if (c == ']' && top != '[') return false;
            if (c == '}' && top != '{') return false;
        }
    }
    return stack.isEmpty();
}

⏱️ Complexity

Time: O(N). We process each character exactly once.

Space: O(N). In the worst case (all opening brackets), the stack stores N elements.

Sub-Pattern 2: Monotonic Stack (Next Greater Element)

💡 Core Concept

A Monotonic Stack keeps its elements in a sorted order (either strictly increasing or strictly decreasing). It is primarily used to find the Next Greater Element (NGE) or Next Smaller Element (NSE) for every element in O(N) time.

🧠 Step-by-Step Intuition

  • Iterate through the array. We will store indices in the stack, not values.
  • While the stack is not empty AND the current element is greater than the element at the top of the stack:
    • This means the current element is the "Next Greater Element" for the top element!
    • Pop the top index and record the current element as its NGE.
  • Push the current index onto the stack.
  • By doing this, the stack always remains decreasing from bottom to top.

public int[] nextGreaterElement(int[] nums) {
    int[] result = new int[nums.length];
    Arrays.fill(result, -1);
    Deque<Integer> stack = new ArrayDeque<>();
    
    for (int i = 0; i < nums.length; i++) {
        // Pop while current is greater than stack top
        while (!stack.isEmpty() && nums[i] > nums[stack.peek()]) {
            int index = stack.pop();
            result[index] = nums[i];
        }
        stack.push(i);
    }
    return result;
}

⏱️ Complexity

Time: O(N). Each element is pushed and popped at most once.

Space: O(N). For the stack and result array.

Sub-Pattern 3: Largest Rectangle in Histogram

💡 Core Concept

We need to find the largest rectangular area in a histogram. For any bar, the maximum rectangle it can form is determined by the nearest smaller bar to its left and the nearest smaller bar to its right. A Monotonic Stack finds these boundaries efficiently.

🧠 Step-by-Step Intuition

  • Maintain an increasing monotonic stack of indices.
  • When we encounter a bar that is shorter than the bar at the top of the stack, we know the current bar is the right boundary.
  • We pop the top bar (this is the height of our rectangle).
  • The new top of the stack is the left boundary.
  • Width = current_index - left_boundary_index - 1.
  • Calculate area = height * width, and update the maximum.
  • To handle the remaining bars in the stack, append a 0 to the end of the heights array (a dummy bar with height 0 forces all remaining bars to be popped and evaluated).

public int largestRectangleArea(int[] heights) {
    Deque<Integer> stack = new ArrayDeque<>();
    int maxArea = 0;
    int n = heights.length;
    
    for (int i = 0; i <= n; i++) {
        // Use 0 as a sentinel to flush the stack
        int currentHeight = (i == n) ? 0 : heights[i];
        
        while (!stack.isEmpty() && currentHeight < heights[stack.peek()]) {
            int height = heights[stack.pop()];
            int leftBoundary = stack.isEmpty() ? -1 : stack.peek();
            int width = i - leftBoundary - 1;
            
            maxArea = Math.max(maxArea, height * width);
        }
        stack.push(i);
    }
    return maxArea;
}

⏱️ Complexity

Time: O(N). Each bar is pushed and popped exactly once.

Space: O(N). For the stack.

💡 Related: This exact logic is used to calculate the maximum rectangle in a binary matrix (Maximal Rectangle). Treat each row as a histogram.

Sub-Pattern 4: Expression Evaluation (RPN)

💡 Core Concept

Reverse Polish Notation (Postfix) places operators after their operands. A stack is the perfect data structure to evaluate these expressions. Whenever we see an operator, we pop the top two numbers, apply the operation, and push the result back.

🧠 Step-by-Step Intuition

  • Initialize a Stack of Integers.
  • Iterate through the string array.
  • If the token is a number, parse it and push it onto the stack.
  • If the token is an operator (+, -, *, /):
    • Pop the top number (this is the second operand).
    • Pop the next number (this is the first operand).
    • Apply the operation: first op second.
    • Push the result back onto the stack.
  • At the end, the stack contains exactly one element: the final answer.

public int evalRPN(String[] tokens) {
    Deque<Integer> stack = new ArrayDeque<>();
    
    for (String token : tokens) {
        if (token.equals("+") || token.equals("-") 
            || token.equals("*") || token.equals("/")) {
            
            int b = stack.pop(); // Second operand
            int a = stack.pop(); // First operand
            
            switch (token) {
                case "+": stack.push(a + b); break;
                case "-": stack.push(a - b); break;
                case "*": stack.push(a * b); break;
                case "/": stack.push(a / b); break;
            }
        } else {
            stack.push(Integer.parseInt(token));
        }
    }
    return stack.pop();
}

⏱️ Complexity

Time: O(N). We iterate through the tokens exactly once.

Space: O(N). Stack stores numbers up to N/2.

⚠️ Order Matters: For subtraction and division, a (first pop) - b (second pop). Reversing them gives the wrong answer.

Sub-Pattern 1: Level Order Traversal (Trees)

💡 Core Concept

BFS explores a graph/tree level by level. It uses a Queue (FIFO) to keep track of nodes to visit next. The core idea is to process all nodes at the current depth before moving deeper.

🧠 Step-by-Step Intuition

  • Initialize a Queue and add the root node.
  • While the queue is not empty:
    • Capture the size of the queue. This is the number of nodes at the current level.
    • Loop size times to process exactly the current level.
    • Pop the node, add its value to the current level's list, and push its left/right children into the queue.
  • Add the level list to the final result.

👀 Visual Dry Run

📝 Java Implementation

public List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> result = new ArrayList<>();
    if (root == null) return result;
    
    Queue<TreeNode> queue = new LinkedList<>();
    queue.offer(root);
    
    while (!queue.isEmpty()) {
        int size = queue.size(); // Crucial step
        List<Integer> level = new ArrayList<>();
        
        for (int i = 0; i < size; i++) {
            TreeNode node = queue.poll();
            level.add(node.val);
            
            if (node.left != null) queue.offer(node.left);
            if (node.right != null) queue.offer(node.right);
        }
        result.add(level);
    }
    return result;
}

⏱️ Complexity

Time: O(N). Every node is visited exactly once.

Space: O(N). The queue holds at most N/2 nodes (last level).

💡 Pro Tip: Always capture int size = queue.size() before the `for` loop. This ensures you only process the current level, even as you add children.

Sub-Pattern 2: Shortest Path in Unweighted Grid

💡 Core Concept

BFS is guaranteed to find the shortest path in an unweighted graph (every edge has the same cost). The first time we reach the destination, it is guaranteed to be via the shortest path.

🧠 Step-by-Step Intuition

  • Initialize a Queue for coordinates (row, col) and a visited set/2D array.
  • Push the starting coordinate and mark it visited.
  • While the queue is not empty:
    • Pop the current cell.
    • If it's the destination, return the distance.
    • Explore all 4 valid neighbors (Up, Down, Left, Right).
    • If a neighbor is valid, unvisited, and not an obstacle, mark visited and push it to the queue with distance + 1.

public int shortestPath(int[][] grid) {
    int rows = grid.length, cols = grid[0].length;
    boolean[][] visited = new boolean[rows][cols];
    Queue<int[]> queue = new LinkedList<>();
    
    queue.offer(new int[]{0, 0, 0}); // r, c, dist
    visited[0][0] = true;
    
    int[][] dirs = {{0,1},{1,0},{0,-1},{-1,0}};
    
    while (!queue.isEmpty()) {
        int[] curr = queue.poll();
        int r = curr[0], c = curr[1], dist = curr[2];
        
        if (r == rows - 1 && c == cols - 1) return dist;
        
        for (int[] dir : dirs) {
            int nr = r + dir[0], nc = c + dir[1];
            if (nr >= 0 && nr < rows && nc >= 0 && nc < cols 
                && grid[nr][nc] == 0 && !visited[nr][nc]) {
                visited[nr][nc] = true;
                queue.offer(new int[]{nr, nc, dist + 1});
            }
        }
    }
    return -1; // Path not found
}

⏱️ Complexity

Time: O(M * N). Each cell is visited at most once.

Space: O(M * N). For the queue and visited array.

Sub-Pattern 3: Multi-Source BFS

💡 Core Concept

Instead of starting from a single source, we start BFS from multiple sources simultaneously. We push all sources into the queue initially. This effectively simulates all sources spreading outward at the same speed.

🧠 Step-by-Step Intuition (Rotting Oranges)

  • Scan the grid. Count fresh oranges. Push all initially rotten oranges into the queue with time=0.
  • While the queue is not empty:
    • Pop a rotten orange.
    • Check its 4 neighbors. If a neighbor is a fresh orange:
      • Make it rotten (change value to 2).
      • Decrement the fresh orange count.
      • Push it to the queue with time + 1.
  • At the end, if the fresh count is 0, return the max time. Else, return -1.

public int orangesRotting(int[][] grid) {
    Queue<int[]> queue = new LinkedList<>();
    int fresh = 0, time = 0;
    int rows = grid.length, cols = grid[0].length;
    
    // 1. Initialize queue with all rotten oranges
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {
            if (grid[r][c] == 2) queue.offer(new int[]{r, c});
            else if (grid[r][c] == 1) fresh++;
        }
    }
    
    int[][] dirs = {{0,1},{1,0},{0,-1},{-1,0}};
    
    // 2. Multi-source BFS
    while (!queue.isEmpty() && fresh > 0) {
        int size = queue.size();
        for (int i = 0; i < size; i++) {
            int[] curr = queue.poll();
            for (int[] dir : dirs) {
                int nr = curr[0] + dir[0], nc = curr[1] + dir[1];
                if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && grid[nr][nc] == 1) {
                    grid[nr][nc] = 2;
                    fresh--;
                    queue.offer(new int[]{nr, nc});
                }
            }
        }
        time++;
    }
    return fresh == 0 ? time : -1;
}

⏱️ Complexity

Time: O(M * N). Each cell is processed once.

Space: O(M * N). Queue size.

💡 Key Insight: The moment you push multiple sources into the queue, they all start expanding level-by-level together, which correctly computes the minimum time for all sources to meet.

Sub-Pattern 4: State Graph BFS (Word Ladder)

💡 Core Concept

Sometimes the "graph" isn't explicitly given as nodes and edges. The nodes are valid states (e.g., words), and the edges are valid transformations (e.g., changing one letter). BFS is used to find the shortest transformation sequence.

🧠 Step-by-Step Intuition

  • Put the beginWord in the queue. Store the word list in a HashSet for O(1) lookups.
  • While the queue is not empty:
    • Pop the current word.
    • Generate all possible "next words" by changing each character from 'a' to 'z'.
    • If the generated word is in the HashSet (and not visited):
      • If it equals endWord, return the current distance + 1.
      • Otherwise, push it to the queue and remove it from the HashSet (to mark it visited).

public int ladderLength(String beginWord, String endWord, List<String> wordList) {
    Set<String> dict = new HashSet<>(wordList);
    if (!dict.contains(endWord)) return 0;
    
    Queue<String> queue = new LinkedList<>();
    queue.offer(beginWord);
    int level = 1;
    
    while (!queue.isEmpty()) {
        int size = queue.size();
        for (int i = 0; i < size; i++) {
            String word = queue.poll();
            char[] chars = word.toCharArray();
            
            for (int j = 0; j < chars.length; j++) {
                char original = chars[j];
                for (char c = 'a'; c <= 'z'; c++) {
                    chars[j] = c;
                    String nextWord = String.valueOf(chars);
                    
                    if (dict.contains(nextWord)) {
                        if (nextWord.equals(endWord)) return level + 1;
                        queue.offer(nextWord);
                        dict.remove(nextWord); // Mark visited
                    }
                }
                chars[j] = original; // Restore
            }
        }
        level++;
    }
    return 0;
}

⏱️ Complexity

Time: O(M² * N) where M is word length, N is number of words. Generating neighbors takes O(M), substring creation O(M).

Space: O(M * N) for the queue and dictionary.

Sub-Pattern 1: Tree Traversal (Pre/In/Post-order)

💡 Core Concept

DFS explores a graph/tree by going as deep as possible along each branch before backtracking. It naturally uses a Stack (or the Call Stack via Recursion). It is the foundation for Backtracking, Path Finding, and Topological Sort.

🧠 Step-by-Step Intuition

  • Base Case: If the node is null, return.
  • Pre-order (Root, Left, Right): Process the current node, then recurse left, then recurse right.
  • In-order (Left, Root, Right): Recurse left, process current, recurse right. (Gives sorted order for BST).
  • Post-order (Left, Right, Root): Recurse left, recurse right, process current. (Used for deletion or calculating heights).

public void preorder(TreeNode root, List<Integer> res) {
    if (root == null) return; // Base Case
    
    res.add(root.val); // Process Current
    preorder(root.left, res); // Go Left
    preorder(root.right, res); // Go Right
}

Sub-Pattern 2: Grid Traversal (Flood Fill / Islands)

💡 Core Concept

Treat a 2D matrix as a graph where each cell is a node connected to its 4 neighbors (Up, Down, Left, Right). DFS is used to explore an entire "island" (connected component) of valid cells.

🧠 Step-by-Step Intuition (Number of Islands)

  • Iterate through every cell in the grid.
  • If a cell is '1' (land): Increment the island count.
  • Trigger DFS from that cell to "sink" the island.
  • DFS Function:
    • Base Case: If out of bounds OR cell is '0' (water), return.
    • Mark Visited: Change the cell to '0' (sink it) to prevent infinite loops.
    • Recursively call DFS on all 4 neighbors.

public int numIslands(char[][] grid) {
    int count = 0;
    for (int i = 0; i < grid.length; i++) {
        for (int j = 0; j < grid[0].length; j++) {
            if (grid[i][j] == '1') {
                count++;
                dfs(grid, i, j);
            }
        }
    }
    return count;
}

private void dfs(char[][] grid, int r, int c) {
    // Base Case: Out of bounds or water
    if (r < 0 || r >= grid.length || c < 0 
        || c >= grid[0].length || grid[r][c] == '0') {
        return;
    }
    
    grid[r][c] = '0'; // Mark visited
    dfs(grid, r + 1, c);
    dfs(grid, r - 1, c);
    dfs(grid, r, c + 1);
    dfs(grid, r, c - 1);
}

⏱️ Complexity

Time: O(M * N). Each cell is visited at most twice (once in the loop, once in DFS).

Space: O(M * N). Worst-case recursion depth if the grid is one giant island.

Sub-Pattern 3: Path Finding (Root-to-Leaf Paths)

💡 Core Concept

DFS is ideal for exploring all possible paths from root to leaf. We carry a state (current path list, current sum) down the recursion tree. When we hit a leaf, we process the path.

🧠 Step-by-Step Intuition (Path Sum II)

  • Pass the current path (List) and current sum as arguments.
  • If node is null, return.
  • Add node's value to the path and sum.
  • Leaf Check: If node is a leaf (left == null && right == null), check if the sum matches the target. If so, add a copy of the path to the result.
  • Recurse left and right.
  • Backtrack: Remove the current node's value from the path before returning to the parent.

public List<List<Integer>> pathSum(TreeNode root, int target) {
    List<List<Integer>> res = new ArrayList<>();
    dfs(root, target, new ArrayList<>(), res);
    return res;
}

private void dfs(TreeNode node, int remain, List<Integer> path, 
                 List<List<Integer>> res) {
    if (node == null) return;
    
    path.add(node.val);
    remain -= node.val;
    
    // Leaf check and target match
    if (node.left == null && node.right == null && remain == 0) {
        res.add(new ArrayList<>(path)); // Deep copy!
    }
    
    dfs(node.left, remain, path, res);
    dfs(node.right, remain, path, res);
    
    // BACKTRACK: remove current node
    path.remove(path.size() - 1);
}

⏱️ Complexity

Time: O(N²). In the worst case (skewed tree), we traverse N nodes, and copying the path takes O(N).

Space: O(N). The path list and recursion stack.

Sub-Pattern 4: Graph Cycle Detection (Coloring)

💡 Core Concept

To detect a cycle in a Directed Graph, we use 3 states (colors):
0 = Unvisited, 1 = Visiting (in current path), 2 = Visited (fully processed). If we encounter a node with state 1 during DFS, we found a back-edge, meaning a cycle exists.

🧠 Step-by-Step Intuition

  • Initialize a state array of size N, filled with 0.
  • Iterate through all nodes. If a node is unvisited (0), start DFS.
  • DFS Function:
    • Mark current node as Visiting (1).
    • For each neighbor:
      • If neighbor is Visiting (1): Cycle detected! Return false.
      • If neighbor is Unvisited (0): Recurse. If recursion returns false, propagate false.
    • Mark current node as Visited (2).

📝 Java Implementation

public boolean canFinish(int numCourses, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    for (int[] pre : prerequisites) adj.get(pre[1]).add(pre[0]);
    
    int[] state = new int[numCourses]; // 0=unvisited, 1=visiting, 2=visited
    
    for (int i = 0; i < numCourses; i++) {
        if (state[i] == 0) {
            if (hasCycle(i, adj, state)) return false;
        }
    }
    return true;
}

private boolean hasCycle(int node, List<List<Integer>> adj, int[] state) {
    if (state[node] == 1) return true;  // Cycle!
    if (state[node] == 2) return false; // Already safe
    
    state[node] = 1; // Mark visiting
    for (int neighbor : adj.get(node)) {
        if (hasCycle(neighbor, adj, state)) return true;
    }
    state[node] = 2; // Mark fully visited
    return false;
}

⏱️ Complexity

Time: O(V + E). Each node and edge is visited once.

Space: O(V + E). The adjacency list and recursion stack.

2. Forgetting to Backtrack

In path-finding or permutations, failing to remove the current element from the path before returning causes state pollution.

When adding a path to the result list, always do new ArrayList(path). If you add the reference, it will be empty or mutated at the end.

Sub-Pattern 1: Subsets / Combinations (Include/Exclude)

💡 Core Concept

Backtracking is an algorithmic technique for solving problems recursively by trying to build a solution incrementally, one piece at a time. If a partial solution is invalid, we backtrack (undo the last choice) and try a different path. It is essentially a DFS on a Decision Tree.

🧠 Step-by-Step Intuition

For subsets, at each element, we have exactly two choices: Include it or Exclude it.

  • Start with an empty current list and index i = 0.
  • If i == nums.length, we have made a decision for every element. Add a copy of current to the result.
  • Decision 1 (Include): Add nums[i] to current. Recurse with i + 1. Backtrack: Remove nums[i] from current.
  • Decision 2 (Exclude): Recurse with i + 1 (without adding nums[i]).

Include 2:
Current: [1, 2]. Base case! Add [1, 2]. Backtrack (remove 2).
Exclude 2:
Current: [1]. Base case! Add [1]. Backtrack (remove 1).
Exclude 1:
Current: []. Recurse to 2.
Include 2:
Current: [2]. Add [2]. Backtrack.
Exclude 2:
Current: []. Add [].

📝 Java Implementation

public List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(0, nums, new ArrayList<>(), res);
    return res;
}

private void backtrack(int i, int[] nums, 
                       List<Integer> current, List<List<Integer>> res) {
    if (i == nums.length) {
        res.add(new ArrayList<>(current)); // Deep copy
        return;
    }
    
    // Decision 1: Include
    current.add(nums[i]);
    backtrack(i + 1, nums, current, res);
    current.remove(current.size() - 1); // Backtrack
    
    // Decision 2: Exclude
    backtrack(i + 1, nums, current, res);
}

⏱️ Complexity

Time: O(N * 2^N). We make 2^N subsets, and copying them takes O(N).

Space: O(N). The recursion depth is N, and the current list holds at most N elements.

Sub-Pattern 2: Permutations (Order Matters)

💡 Core Concept

In permutations, order matters. At each step, we can pick any unused element from the array. We use a boolean[] used array to track which elements have already been placed in the current permutation path.

🧠 Step-by-Step Intuition

  • Maintain a boolean[] used array of the same size as nums.
  • Loop through all elements from index 0 to N-1.
  • If used[i] is true, skip it (it's already in our current permutation).
  • If not used:
    • Mark used[i] = true.
    • Add nums[i] to current path.
    • Recurse.
    • Backtrack: Remove nums[i] and set used[i] = false.

Pick 3:
Path: [1, 3]. Pick 2 -> [1, 3, 2]. Add to result.
Pick 2:

📝 Java Implementation

public List<List<Integer>> permute(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    boolean[] used = new boolean[nums.length];
    backtrack(nums, used, new ArrayList<>(), res);
    return res;
}

private void backtrack(int[] nums, boolean[] used, 
                       List<Integer> current, List<List<Integer>> res) {
    if (current.size() == nums.length) {
        res.add(new ArrayList<>(current));
        return;
    }
    
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue; // Skip used elements
        
        used[i] = true;
        current.add(nums[i]);
        
        backtrack(nums, used, current, res);
        
        // Backtrack
        current.remove(current.size() - 1);
        used[i] = false;
    }
}

⏱️ Complexity

Time: O(N * N!). There are N! permutations, and copying each takes O(N).

Space: O(N). For the recursion stack and the `used` array.

Sub-Pattern 3: Combination Sum (Reusing Elements)

💡 Core Concept

We need to find combinations of numbers that sum to a target. The key difference here is that we can reuse the same element multiple times. We use a start index to avoid duplicate combinations (e.g., [2,2,3] and [3,2,2] are the same).

🧠 Step-by-Step Intuition

  • Sort the array first. This enables pruning (if current sum > target, stop).
  • Pass a start index to the recursive function.
  • Loop from i = start to N-1.
  • If sum + nums[i] > target, break (because array is sorted, adding larger numbers will only exceed the target).
  • Add nums[i] to path.
  • Recurse with the SAME index i (to allow reusing the element).
  • Backtrack: Remove the element.

Pick 2:

Pick 3:
Path: [2,2,3]. Sum=7. Add to result!
Pick 7:

public List<List<Integer>> combinationSum(int[] candidates, int target) {
    List<List<Integer>> res = new ArrayList<>();
    Arrays.sort(candidates); // Crucial for pruning
    backtrack(candidates, target, 0, new ArrayList<>(), res);
    return res;
}

private void backtrack(int[] candidates, int remain, int start,
                       List<Integer> current, List<List<Integer>> res) {
    if (remain == 0) {
        res.add(new ArrayList<>(current));
        return;
    }
    
    for (int i = start; i < candidates.length; i++) {
        // Pruning: array is sorted, so no need to check further
        if (candidates[i] > remain) break;
        
        current.add(candidates[i]);
        // Recurse with 'i' (not i+1) to allow reuse
        backtrack(candidates, remain - candidates[i], i, current, res);
        current.remove(current.size() - 1);
    }
}

⏱️ Complexity

Time: O(N^(T/M)). Where T is the target, M is the smallest element.

Space: O(T/M). Recursion depth.

Sub-Pattern 4: Grid Path Search (Word Search)

💡 Core Concept

We use DFS on a 2D grid to find a specific sequence of characters. Since we cannot reuse the same cell in the same path, we must backtrack by marking the cell as visited before exploring neighbors, and unmarking it before returning.

🧠 Step-by-Step Intuition

  • Iterate through every cell in the grid. If grid[r][c] == word[0], start DFS.
  • DFS Function (r, c, index):
    • If index == word.length, we found the word!
    • If out of bounds, or grid[r][c] != word[index], return false.
    • Mark Visited: Store the original character, and set grid[r][c] = '#'.
    • Recursively check all 4 neighbors with index + 1.
    • Backtrack: Restore grid[r][c] = originalChar.

public boolean exist(char[][] board, String word) {
    for (int i = 0; i < board.length; i++) {
        for (int j = 0; j < board[0].length; j++) {
            if (dfs(board, word, i, j, 0)) return true;
        }
    }
    return false;
}

private boolean dfs(char[][] board, String word, int r, int c, int idx) {
    if (idx == word.length()) return true;
    if (r < 0 || r >= board.length || c < 0 
        || c >= board[0].length || board[r][c] != word.charAt(idx)) {
        return false;
    }
    
    char temp = board[r][c];
    board[r][c] = '#'; // Mark visited
    
    boolean found = dfs(board, word, r+1, c, idx+1) ||
                    dfs(board, word, r-1, c, idx+1) ||
                    dfs(board, word, r, c+1, idx+1) ||
                    dfs(board, word, r, c-1, idx+1);
                    
    board[r][c] = temp; // Backtrack
    return found;
}

⏱️ Complexity

Time: O(M * N * 4^L). Where L is the length of the word. We start from M*N cells, and branch 4 ways.

Space: O(L). Recursion depth.

Sub-Pattern 1: Top K Elements (Kth Largest)

💡 Core Concept

A Heap (or Priority Queue) is a specialized tree-based data structure that allows O(1) access to the minimum or maximum element, with O(log N) insertions and deletions. Java's `PriorityQueue` is a Min-Heap by default.

🧠 Step-by-Step Intuition (Kth Largest Element)

To find the Kth largest element, we maintain a Min-Heap of size K.

  • Iterate through the array. Push elements onto the heap.
  • If the heap size exceeds K, pop the smallest element.
  • After processing all numbers, the heap contains exactly the K largest elements.
  • The smallest among them (the root of the Min-Heap) is exactly the Kth largest!

Heap: [3, 5, 6]. Pop 3. Heap: [5, 6].

📝 Java Implementation

public int findKthLargest(int[] nums, int k) {
    // Default is Min-Heap
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();
    
    for (int num : nums) {
        minHeap.offer(num);
        if (minHeap.size() > k) {
            minHeap.poll(); // Remove smallest
        }
    }
    
    // The root is the Kth largest
    return minHeap.peek();
}

⏱️ Complexity

Time: O(N log K). Iterating through N elements, each heap operation takes O(log K).

Space: O(K). The heap holds at most K elements.

💡 Max-Heap in Java: Use new PriorityQueue<>(Collections.reverseOrder()) or a lambda (a, b) -> b - a.

Sub-Pattern 2: K-Way Merge (Merge K Sorted Lists)

💡 Core Concept

When merging K sorted lists, a Min-Heap is used to efficiently find the smallest element among the heads of all K lists. We push the head of each list into the heap, extract the minimum, and push its `next` node.

🧠 Step-by-Step Intuition

  • Create a Min-Heap that compares the values of ListNodes.
  • Add the head of each of the K lists to the heap (if not null).
  • Create a dummy node to build the result list.
  • While the heap is not empty:
    • Pop the smallest node.
    • Append it to the result list.
    • If the popped node has a next, push it onto the heap.

public ListNode mergeKLists(ListNode[] lists) {
    if (lists == null || lists.length == 0) return null;
    
    // Custom comparator for ListNode
    PriorityQueue<ListNode> heap = new PriorityQueue<>(
        (a, b) -> a.val - b.val
    );
    
    // Add heads of all lists
    for (ListNode node : lists) {
        if (node != null) heap.offer(node);
    }
    
    ListNode dummy = new ListNode(0);
    ListNode curr = dummy;
    
    while (!heap.isEmpty()) {
        ListNode node = heap.poll();
        curr.next = node;
        curr = curr.next;
        
        if (node.next != null) {
            heap.offer(node.next);
        }
    }
    
    return dummy.next;
}

⏱️ Complexity

Time: O(N log K). Where N is the total number of nodes across all lists, K is the number of lists. Each insertion takes O(log K).

Space: O(K). The heap stores at most K nodes.

Sub-Pattern 3: Two Heaps (Running Median)

💡 Core Concept

To find the median of a data stream efficiently, we use two heaps: a Max-Heap for the smaller half of the data, and a Min-Heap for the larger half. The median is either the top of one heap or the average of both tops.

🧠 Step-by-Step Intuition

  • Max-Heap (small): Stores the smaller half. Top is the largest of the small numbers.
  • Min-Heap (large): Stores the larger half. Top is the smallest of the large numbers.
  • Balance Rule: small.size() should be equal to or exactly 1 greater than large.size().
  • Add Number: Always add to `small`. Then move the largest from `small` to `large` to ensure order. Finally, rebalance if `small` is smaller than `large`.

👀 Visual Dry Run

Add 1:

Add 2:
Small: [1], Large: [2]. Median = (1+2)/2 = 1.5.
Add 3:
Small: [2, 1], Large: [3]. Median = 2 (top of Small).

📝 Java Implementation

class MedianFinder {
    // Max-Heap for smaller half
    PriorityQueue<Integer> small = new PriorityQueue<>(Collections.reverseOrder());
    // Min-Heap for larger half
    PriorityQueue<Integer> large = new PriorityQueue<>();
    
    public void addNum(int num) {
        small.offer(num);
        large.offer(small.poll()); // Ensure order
        
        // Rebalance sizes
        if (small.size() < large.size()) {
            small.offer(large.poll());
        }
    }
    
    public double findMedian() {
        if (small.size() > large.size()) {
            return small.peek();
        }
        return (small.peek() + large.peek()) / 2.0;
    }
}

⏱️ Complexity

Time: O(log N) for `addNum`, O(1) for `findMedian`.

Space: O(N). To store the stream of numbers.

💡 Remember: `small` is a Max-Heap (so `peek()` gives the largest of the smaller half). `large` is a Min-Heap.

Sub-Pattern 4: Greedy + Heap (Task Scheduler)

💡 Core Concept

When we need to process the most frequent or largest elements first while respecting a constraint (like a cooldown period), we use a Max-Heap to always pick the best available option, and a Queue to manage the cooldown state.

🧠 Step-by-Step Intuition (Task Scheduler)

  • Count the frequency of each task using a Hash Map.
  • Push all frequencies into a Max-Heap.
  • Use a Queue to track tasks that are in the cooldown period (store `[remaining_freq, available_time]`).
  • Iterate through time. At each time unit:
    • If the heap is not empty, pop the most frequent task, decrement its frequency, and if it's still > 0, push it to the Queue with `time + n`.
    • If the Queue's front is available at this time, move it back to the Max-Heap.

public int leastInterval(char[] tasks, int n) {
    int[] freq = new int[26];
    for (char c : tasks) freq[c - 'A']++;
    
    PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
    for (int f : freq) {
        if (f > 0) maxHeap.offer(f);
    }
    
    Queue<int[]> cooldown = new LinkedList<>();
    int time = 0;
    
    while (!maxHeap.isEmpty() || !cooldown.isEmpty()) {
        time++;
        
        if (!maxHeap.isEmpty()) {
            int count = maxHeap.poll() - 1;
            if (count > 0) {
                cooldown.offer(new int[]{count, time + n});
            }
        }
        
        if (!cooldown.isEmpty() && cooldown.peek()[1] == time) {
            maxHeap.offer(cooldown.poll()[0]);
        }
    }
    
    return time;
}

⏱️ Complexity

Time: O(N). Where N is the total number of tasks. We process each task once.

Space: O(1). The heap and queue store at most 26 characters.

Sub-Pattern 1: Interval Scheduling (Sort by End)

💡 Core Concept

A Greedy algorithm makes the locally optimal choice at each step, hoping to find the globally optimal solution. It never backtracks. For interval problems (e.g., maximum non-overlapping meetings), the optimal choice is always to pick the interval that ends earliest.

🧠 Step-by-Step Intuition

  • Sort the intervals based on their end time in ascending order.
  • Initialize a count (or keep track of the last end time).
  • Iterate through the sorted intervals.
  • If the current interval's start time is greater than or equal to the previous end time, we can take it!
  • Update the end time and increment the count.

👀 Visual Dry Run: Non-Overlapping Intervals

Check [4,6]:

public int maxNonOverlapping(int[][] intervals) {
    // Sort by end time (ascending)
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));
    
    int count = 0;
    int lastEnd = Integer.MIN_VALUE;
    
    for (int[] interval : intervals) {
        if (interval[0] >= lastEnd) {
            count++;
            lastEnd = interval[1]; // Update end
        }
    }
    return count;
}

⏱️ Complexity

Time: O(N log N). Sorting dominates the time complexity. The iteration takes O(N).

Space: O(1) or O(log N). Depending on the sorting algorithm's space complexity.

Sub-Pattern 2: Reachability (Jump Game)

💡 Core Concept

Instead of trying all possible jump combinations (O(2^N)), we only care about the maximum index we can reach. If we can reach the end, return true. The greedy choice is to always extend our maximum reach as far as possible.

🧠 Step-by-Step Intuition

  • Maintain a variable maxReach = 0.
  • Iterate through the array with index i.
  • If i > maxReach, we cannot reach this index! Return false.
  • Update maxReach = Math.max(maxReach, i + nums[i]).
  • If maxReach >= nums.length - 1, we can reach the end.

public boolean canJump(int[] nums) {
    int maxReach = 0;
    
    for (int i = 0; i < nums.length; i++) {
        // Cannot even reach index i
        if (i > maxReach) return false;
        
        // Extend the maximum reach
        maxReach = Math.max(maxReach, i + nums[i]);
        
        if (maxReach >= nums.length - 1) {
            return true;
        }
    }
    return true;
}

Sub-Pattern 3: Circular Greedy (Gas Station)

💡 Core Concept

If the total gas is greater than the total cost, a valid starting station is guaranteed to exist. We can find it in one pass: if our tank goes negative at station `i`, it means we cannot start at any station between our previous start and `i`. Thus, the next possible start is `i + 1`.

🧠 Step-by-Step Intuition

  • Track totalSurplus (to check if a solution exists).
  • Track currentTank (to find the starting point).
  • Iterate through each station:
    • currentTank += gas[i] - cost[i].
    • totalSurplus += gas[i] - cost[i].
    • If currentTank < 0, we cannot reach `i+1` from our current start. Set start = i + 1 and reset currentTank = 0.
  • At the end, if totalSurplus >= 0, return start. Else, return -1.

👀 Visual Dry Run

i=2:
Tank = 3-5 = -2. < 0. Start = 3, Tank = 0.

Tank = 4-1 = 3. >= 0.

Tank = 3 + 5-2 = 6. TotalSurplus = 1 >= 0. Return start 3.

📝 Java Implementation

public int canCompleteCircuit(int[] gas, int[] cost) {
    int totalSurplus = 0;
    int currentTank = 0;
    int start = 0;
    
    for (int i = 0; i < gas.length; i++) {
        int net = gas[i] - cost[i];
        totalSurplus += net;
        currentTank += net;
        
        // Cannot reach next station
        if (currentTank < 0) {
            start = i + 1;  // Reset start
            currentTank = 0; // Reset tank
        }
    }
    
    return totalSurplus >= 0 ? start : -1;
}

⏱️ Complexity

Time: O(N). One pass through the gas station arrays.

Space: O(1). Only integer variables used.

Sub-Pattern 4: Two-Pass Greedy (Candy)

💡 Core Concept

Sometimes, a single greedy pass is insufficient because a choice depends on both the left neighbor and the right neighbor. We can solve this by making a left-to-right pass, followed by a right-to-left pass, and combining the results.

🧠 Step-by-Step Intuition (Candy)

  • Initialize a candies array with all 1s (every child gets at least 1).
  • Left-to-Right Pass: If ratings[i] > ratings[i-1], then candies[i] = candies[i-1] + 1.
  • Right-to-Left Pass: If ratings[i] > ratings[i+1], then candies[i] = Math.max(candies[i], candies[i+1] + 1).
  • Sum up the candies array.

public int candy(int[] ratings) {
    int n = ratings.length;
    int[] candies = new int[n];
    Arrays.fill(candies, 1); // Everyone gets 1
    
    // Left to Right
    for (int i = 1; i < n; i++) {
        if (ratings[i] > ratings[i - 1]) {
            candies[i] = candies[i - 1] + 1;
        }
    }
    
    // Right to Left
    for (int i = n - 2; i >= 0; i--) {
        if (ratings[i] > ratings[i + 1]) {
            candies[i] = Math.max(candies[i], candies[i + 1] + 1);
        }
    }
    
    int total = 0;
    for (int c : candies) total += c;
    return total;
}

⏱️ Complexity

Time: O(N). Three passes (L->R, R->L, Sum).

Space: O(N). For the candies array.

💡 Space Optimization: You can achieve O(1) space using the slope method (counting increasing and decreasing sequences). But the two-pass array is much easier to code in an interview.

Sub-Pattern 1: Merge Intervals (Sweep Line)

💡 Core Concept

Given a collection of intervals, merge all overlapping intervals. The key intuition is to sort the intervals by their start time. Once sorted, we can linearly sweep through them, merging whenever the current interval's start is less than or equal to the previous interval's end.

🧠 Step-by-Step Intuition

  • Sort the intervals based on their start time in ascending order.
  • Initialize a result list and add the first interval to it.
  • Iterate through the remaining intervals:
    • Let lastMerged be the last interval in our result list.
    • If the current interval's start is less than or equal to lastMerged.end, they overlap!
    • Update lastMerged.end = Math.max(lastMerged.end, current.end).
    • If they do not overlap, simply add the current interval to the result list.

15 > 10. Add. Result: [[1,6], [8,10], [15,18]]

📝 Java Implementation

public int[][] merge(int[][] intervals) {
    if (intervals.length <= 1) return intervals;
    
    // Sort by start time
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
    
    List<int[]> result = new ArrayList<>();
    int[] current = intervals[0];
    result.add(current);
    
    for (int[] interval : intervals) {
        if (interval[0] <= current[1]) {
            // Overlap: update end time
            current[1] = Math.max(current[1], interval[1]);
        } else {
            // No overlap: add new
            current = interval;
            result.add(current);
        }
    }
    return result.toArray(new int[result.size()][]);
}

⏱️ Complexity

Time: O(N log N). Sorting dominates. The sweep is O(N).

Space: O(log N) or O(N). Depending on the sorting algorithm and the result list.

Sub-Pattern 2: Insert Interval

💡 Core Concept

Given a set of non-overlapping, sorted intervals, insert a new interval and merge if necessary. Because the input is already sorted, we can do this in O(N) time without re-sorting, using a three-phase approach.

🧠 Step-by-Step Intuition

  • Phase 1 (Before): Add all intervals that end strictly before the new interval starts (interval.end < newInterval.start).
  • Phase 2 (Merge): While intervals overlap with the new interval (interval.start <= newInterval.end), merge them. Update newInterval.start = min(...) and newInterval.end = max(...).
  • Add the fully merged newInterval to the result.
  • Phase 3 (After): Add all remaining intervals.

👀 Visual Dry Run

Existing: [[1,3], [6,9]], New: [2,5]

Phase 1:
[1,3] ends at 3. New starts at 2. 3 > 2. Stop phase 1.
Phase 2:
[1,3] overlaps [2,5]. Merge: New becomes [1,5].
Phase 2:
[6,9] starts at 6. New ends at 5. 6 > 5. No overlap. Stop.
Result:
Add [1,5]. Phase 3 adds [6,9]. Final: [[1,5], [6,9]].

📝 Java Implementation

public int[][] insert(int[][] intervals, int[] newInterval) {
    List<int[]> result = new ArrayList<>();
    int i = 0;
    int n = intervals.length;
    
    // 1. Add intervals strictly before
    while (i < n && intervals[i][1] < newInterval[0]) {
        result.add(intervals[i]);
        i++;
    }
    
    // 2. Merge overlapping intervals
    while (i < n && intervals[i][0] <= newInterval[1]) {
        newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
        newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
        i++;
    }
    result.add(newInterval);
    
    // 3. Add the rest
    while (i < n) {
        result.add(intervals[i]);
        i++;
    }
    
    return result.toArray(new int[result.size()][]);
}

⏱️ Complexity

Time: O(N). We traverse the intervals exactly once.

Space: O(N) or O(1). O(N) if we count the result array, otherwise O(1) auxiliary.

Sub-Pattern 3: Interval Intersection (Two Pointers)

💡 Core Concept

Find the intersection of two lists of sorted, non-overlapping intervals. We use two pointers, one for each list. At each step, we calculate the intersection (if any) and then move the pointer of the interval that ends first.

🧠 Step-by-Step Intuition

  • Maintain pointers i for list A and j for list B.
  • Find the intersection: start = max(A[i].start, B[j].start) and end = min(A[i].end, B[j].end).
  • If start <= end, we have a valid intersection. Add it to the result.
  • Whichever interval has the smaller end time, advance its pointer (it has no chance of intersecting further).
  • Repeat until one list is exhausted.

i=1, j=0:
A[1]=[5,10], B[0]=[1,5]. Intersect: max(5,1)=5, min(10,5)=5. Add [5,5]. B ends first (5<10), so j++.
i=1, j=1:
A[1]=[5,10], B[1]=[8,12]. Intersect: [8,10]. Add. A ends first, i++.

public int[][] intervalIntersection(int[][] A, int[][] B) {
    List<int[]> res = new ArrayList<>();
    int i = 0, j = 0;
    
    while (i < A.length && j < B.length) {
        int start = Math.max(A[i][0], B[j][0]);
        int end = Math.min(A[i][1], B[j][1]);
        
        if (start <= end) {
            res.add(new int[]{start, end});
        }
        
        // Advance the pointer with the smaller end time
        if (A[i][1] < B[j][1]) {
            i++;
        } else {
            j++;
        }
    }
    return res.toArray(new int[res.size()][]);
}

⏱️ Complexity

Time: O(N + M). Where N and M are the lengths of the two arrays.

Space: O(N + M) to store the result, or O(1) auxiliary.

Sub-Pattern 4: Min Removals & Meeting Rooms

💡 Core Concept

To find the minimum removals to make intervals non-overlapping, we are essentially finding the maximum number of non-overlapping intervals (Activity Selection). To find the maximum number of concurrent intervals (Meeting Rooms II), we use a Min-Heap or sweep line.

🧠 Step-by-Step Intuition: Min Removals

  • Sort intervals by their end time (ascending).
  • Track the lastEnd time.
  • Iterate through. If interval.start >= lastEnd, we keep it (no overlap). Update lastEnd = interval.end.
  • Otherwise, it overlaps. We must remove it (increment removals).

🧠 Step-by-Step Intuition: Meeting Rooms II

  • Sort intervals by start time.
  • Use a Min-Heap to store the end times of active meetings.
  • For each interval, if the heap top is ≤ current start, the room is free. Pop it.
  • Push the current end time. The size of the heap is the max rooms needed.

// Minimum Removals (Non-overlapping)
public int eraseOverlapIntervals(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));
    int removals = 0;
    int lastEnd = Integer.MIN_VALUE;
    
    for (int[] interval : intervals) {
        if (interval[0] >= lastEnd) {
            lastEnd = interval[1]; // Keep it
        } else {
            removals++; // Remove it
        }
    }
    return removals;
}
// Meeting Rooms II (Max Overlaps)
public int minMeetingRooms(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    
    for (int[] interval : intervals) {
        if (!heap.isEmpty() && heap.peek() <= interval[0]) {
            heap.poll(); // Room is free
        }
        heap.offer(interval[1]);
    }
    return heap.size();
}

Sub-Pattern 1: In-Place Reversal

💡 Core Concept

Reversing a linked list requires changing the next pointers to point backwards. Because we lose access to the rest of the list when we overwrite curr.next, we must use three pointers: prev, curr, and nextTemp.

🧠 Step-by-Step Intuition

  • Initialize prev = null and curr = head.
  • While curr != null:
    • Save the next node: nextTemp = curr.next (so we don't lose it).
    • Reverse the pointer: curr.next = prev.
    • Advance pointers: prev = curr, curr = nextTemp.
  • At the end, prev is the new head of the reversed list.

👀 Visual Dry Run: Reverse 1 -> 2 -> 3

Init:
prev=null, curr=1. nextTemp=2.
Step 1:
1.next = null. prev=1, curr=2.
Step 2:
2.next = 1. prev=2, curr=3.
Step 3:
3.next = 2. prev=3, curr=null. Return prev (3).

📝 Java Implementation

public ListNode reverseList(ListNode head) {
    ListNode prev = null;
    ListNode curr = head;
    
    while (curr != null) {
        ListNode nextTemp = curr.next; // 1. Save
        curr.next = prev;              // 2. Reverse
        prev = curr;                   // 3. Advance
        curr = nextTemp;               // 4. Advance
    }
    return prev; // New head
}

⏱️ Complexity

Time: O(N). We traverse the list exactly once.

Space: O(1). Only three pointer variables are used.

💡 Recursive Approach: The recursive solution also works and is O(N) space due to the call stack. The iterative solution is preferred for O(1) space.

Sub-Pattern 2: Dummy Node & Merging

💡 Core Concept

A Dummy Node (or sentinel node) is a fake node placed before the head. It eliminates edge cases where the head itself needs to be removed or modified. After building the list, we simply return dummy.next.

🧠 Step-by-Step Intuition (Merge Two Sorted Lists)

  • Create a dummy node. Let tail = dummy.
  • While both lists have nodes:
    • Compare the current values of list1 and list2.
    • Attach the smaller node to tail.next.
    • Advance the pointer of the chosen list.
    • Advance tail = tail.next.
  • Attach the remaining list (if any) to tail.next.
  • Return dummy.next.

👀 Visual Dry Run

📝 Java Implementation

public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
    ListNode dummy = new ListNode(-1);
    ListNode tail = dummy;
    
    while (list1 != null && list2 != null) {
        if (list1.val <= list2.val) {
            tail.next = list1;
            list1 = list1.next;
        } else {
            tail.next = list2;
            list2 = list2.next;
        }
        tail = tail.next;
    }
    
    // Attach the remaining list
    tail.next = (list1 != null) ? list1 : list2;
    
    return dummy.next;
}

⏱️ Complexity

Time: O(N + M). We traverse both lists once.

Space: O(1). We only rearrange the existing nodes, no new nodes are created.

Sub-Pattern 3: Gap Two Pointers (Nth from End)

💡 Core Concept

To find the Nth node from the end in a single pass, maintain a gap of N between a fast and slow pointer. When fast reaches the end, slow is exactly N nodes behind.

🧠 Step-by-Step Intuition

  • Create a dummy node pointing to head. Initialize fast = dummy, slow = dummy.
  • Move fast forward exactly N + 1 steps.
  • Move both fast and slow forward one step at a time until fast becomes null.
  • Now, slow is pointing to the node just before the target. Remove it: slow.next = slow.next.next.
  • Return dummy.next.

public ListNode removeNthFromEnd(ListNode head, int n) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    
    ListNode fast = dummy;
    ListNode slow = dummy;
    
    // Move fast N+1 steps ahead
    for (int i = 0; i <= n; i++) {
        fast = fast.next;
    }
    
    // Move both until fast hits null
    while (fast != null) {
        fast = fast.next;
        slow = slow.next;
    }
    
    // Remove target node
    slow.next = slow.next.next;
    
    return dummy.next;
}

⏱️ Complexity

Time: O(N). One pass. (Fast moves N steps, then both move N-n steps).

Space: O(1).

Sub-Pattern 4: Fast & Slow (Middle, Cycle, Palindrome)

💡 Core Concept

Floyd's Tortoise and Hare. Slow moves 1 step, Fast moves 2 steps. Used to find the middle, detect cycles, or find the start of a cycle.

🧠 Step-by-Step Intuition: Palindrome Linked List

A palindrome reads the same forwards and backwards. We can solve this in O(N) time and O(1) space:

  • Find Middle: Use Fast/Slow pointers.
  • Reverse Second Half: Disconnect the middle and reverse the second half in-place (using the 3-pointer method).
  • Compare: Compare the first half and the reversed second half node by node.
  • Restore (Optional): Reverse the second half back to restore the original list.

📝 Java Implementation

public boolean isPalindrome(ListNode head) {
    // 1. Find middle
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    
    // 2. Reverse second half
    ListNode secondHalf = reverse(slow);
    ListNode firstHalf = head;
    
    // 3. Compare
    while (secondHalf != null) {
        if (firstHalf.val != secondHalf.val) return false;
        firstHalf = firstHalf.next;
        secondHalf = secondHalf.next;
    }
    return true;
}

private ListNode reverse(ListNode head) {
    ListNode prev = null;
    while (head != null) {
        ListNode next = head.next;
        head.next = prev;
        prev = head;
        head = next;
    }
    return prev;
}

⏱️ Complexity

Time: O(N). Three passes (find mid, reverse, compare).

Space: O(1).

💡 Cycle Detection: If `slow == fast`, a cycle exists. To find the start, reset `slow` to `head` and move both by 1 step until they meet again.

Sub-Pattern 5: Advanced Reordering (K-Group)

💡 Core Concept

This combines multiple sub-patterns. We traverse the list, and for every group of K nodes, we reverse them. If the remaining nodes are less than K, we leave them as is. We use a dummy node to hold the result.

🧠 Step-by-Step Intuition

  • Create a dummy node pointing to head.
  • Find the length of the list. (If length < K, return head).
  • Maintain a prevGroupTail pointer (initially at dummy).
  • Loop while there are at least K nodes left:
    • Reverse the next K nodes using the 3-pointer technique.
    • Connect prevGroupTail.next to the new head of the reversed group.
    • Connect the tail of the reversed group to the rest of the list.
    • Move prevGroupTail to the tail of the reversed group.

📝 Java Implementation

public ListNode reverseKGroup(ListNode head, int k) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode prevGroupTail = dummy;
    
    while (true) {
        // Find the Kth node from prevGroupTail
        ListNode kth = prevGroupTail;
        for (int i = 0; i < k && kth != null; i++) {
            kth = kth.next;
        }
        
        // If less than K nodes, break
        if (kth == null) break;
        
        ListNode groupHead = prevGroupTail.next;
        ListNode nextGroupHead = kth.next;
        
        // Reverse K nodes
        ListNode prev = nextGroupHead;
        ListNode curr = groupHead;
        while (curr != nextGroupHead) {
            ListNode next = curr.next;
            curr.next = prev;
            prev = curr;
            curr = next;
        }
        
        // Connect with previous part
        prevGroupTail.next = prev; // prev is new head of group
        prevGroupTail = groupHead; // groupHead is now the tail
    }
    return dummy.next;
}

⏱️ Complexity

Time: O(N). Each node is visited at most twice.

Space: O(1).

💡 Reorder List: Find middle -> Reverse second half -> Merge the two halves alternately.

Sub-Pattern 1: 1D DP (Fibonacci / Climbing Stairs)

💡 Core Concept

1D DP is used when the state depends on a single variable (usually an index). The core idea is that the answer to the current state can be derived from a constant number of previous states. Formula: dp[i] = dp[i-1] + dp[i-2].

🧠 Step-by-Step Intuition

  • Base Cases: Initialize the smallest subproblems (e.g., dp[0] = 1, dp[1] = 1).

  • Space Optimization: Since dp[i] only needs dp[i-1] and dp[i-2], we can use two variables instead of an entire array.

public int climbStairs(int n) {
    if (n <= 1) return 1;
    
    // Space Optimized: O(1) Space
    int prev2 = 1; // dp[0]

        int curr = prev1 + prev2;
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}

Sub-Pattern 2: 2D DP (Unique Paths / Grid)

💡 Core Concept

2D DP is used when the state depends on two variables (e.g., row and column, or two strings). The state dp[i][j] is usually built from the top (dp[i-1][j]) and the left (dp[i][j-1]).

public int uniquePaths(int m, int n) {
    int[][] dp = new int[m][n];
    
    // Base cases: first row and col
    for (int i = 0; i < m; i++) dp[i][0] = 1;
    for (int j = 0; j < n; j++) dp[0][j] = 1;
    
    for (int i = 1; i < m; i++) {
        for (int j = 1; j < n; j++) {
            dp[i][j] = dp[i-1][j] + dp[i][j-1];
        }
    }
    return dp[m-1][n-1];
}

Sub-Pattern 3: 0/1 Knapsack

💡 Core Concept

Given a set of items with weights and values, maximize the total value without exceeding the capacity. Each item can be picked at most once (0/1). At each step, we choose to Include or Exclude the item.

🧠 Step-by-Step Intuition

  • Create a 2D table dp[i][w] where `i` is the item index and `w` is the capacity.
  • If weight > capacity: We cannot include the item. Inherit from above: dp[i-1][w].
  • If weight <= capacity: Take the max of including or excluding.
    max(val[i] + dp[i-1][w-wt[i]], dp[i-1][w]).

public int knapsack(int[] wt, int[] val, int W) {
    int n = wt.length;
    int[][] dp = new int[n + 1][W + 1];
    
    for (int i = 1; i <= n; i++) {
        for (int w = 1; w <= W; w++) {
            if (wt[i - 1] <= w) {
                dp[i][w] = Math.max(
                    val[i - 1] + dp[i - 1][w - wt[i - 1]], 
                    dp[i - 1][w]
                );
            } else {
                dp[i][w] = dp[i - 1][w];
            }
        }
    }
    return dp[n][W];
}

⏱️ Complexity

Time: O(N * W). N items, W capacity.

Space: O(N * W). Can be optimized to 1D array of size W (iterate backwards).

💡 Variant: For Unbounded Knapsack (Coin Change), iterate the inner loop forwards (w = wt[i]; w <= W; w++).

💡 Core Concept

public int lengthOfLIS(int[] nums) {
    if (nums.length == 0) return 0;
    int[] dp = new int[nums.length];
    Arrays.fill(dp, 1);

            if (nums[j] < nums[i]) {

    }
    return maxLIS;
}

Sub-Pattern 5: Digit DP

💡 Core Concept

Digit DP is used to count the number of integers in a range [0, N] that satisfy a specific property (e.g., no consecutive 1s, digits sum to K, etc.). We process the number digit by digit from left to right.

🧠 Step-by-Step Intuition

  • State: dp(index, tight, prev).
  • index: Current digit position we are filling.
  • tight: Boolean. If true, the current digit is bounded by the digit of `N` (we can't just pick any number 0-9). If false, we can pick 0-9 freely.
  • prev: The previously chosen digit (needed for properties like consecutive digits).
  • Base Case: If index == length, return 1 (we formed a valid number).

👀 Visual Dry Run

Count numbers with unique digits from 0 to N

We build a recursion tree, branching from 0 to 9. If tight is true, we only branch up to the current digit of N. We memoize the (index, tight, prev) states.

📝 Java Implementation

public int countNumbers(int n) {
    char[] digits = String.valueOf(n).toCharArray();
    int[][][] memo = new int[digits.length][2][10];
    for (int[][] m : memo) for (int[] row : m) Arrays.fill(row, -1);
    return dfs(0, 1, -1, digits, memo);
}

private int dfs(int idx, int tight, int prev, char[] digits, int[][][] memo) {
    if (idx == digits.length) return 1; // Valid number
    if (memo[idx][tight][prev + 1] != -1) return memo[idx][tight][prev + 1];
    
    int limit = tight == 1 ? digits[idx] - '0' : 9;
    int res = 0;
    
    for (int d = 0; d <= limit; d++) {
        if (d == prev) continue; // Property: unique digits
        res += dfs(idx + 1, (tight == 1 && d == limit) ? 1 : 0, d, digits, memo);
    }
    return memo[idx][tight][prev + 1] = res;
}

Sub-Pattern 1: Dijkstra (Shortest Path)

💡 Core Concept

Dijkstra's algorithm finds the shortest path from a single source to all other nodes in a weighted graph with non-negative edge weights. It uses a Priority Queue (Min-Heap) to greedily pick the node with the smallest known distance.

🧠 Step-by-Step Intuition

  • Initialize a dist array with Integer.MAX_VALUE. Set dist[src] = 0.
  • Push [0, src] to a Min-Heap (Priority Queue).
  • While the heap is not empty:
    • Pop the node with the smallest distance.
    • If the popped distance > dist[node], skip (outdated entry).
    • For each neighbor, if dist[node] + weight < dist[neighbor], update and push to heap.

public int networkDelayTime(int[][] times, int n, int k) {
    List<List<int[]>> adj = new ArrayList<>();
    for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());
    for (int[] t : times) adj.get(t[0]).add(new int[]{t[1], t[2]});
    
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    pq.offer(new int[]{0, k}); // [dist, node]
    
    int[] dist = new int[n + 1];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[k] = 0;
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        if (d > dist[u]) continue;
        
        for (int[] edge : adj.get(u)) {
            int v = edge[0], w = edge[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.offer(new int[]{dist[v], v});
            }
        }
    }
    int max = 0;
    for (int i = 1; i <= n; i++) max = Math.max(max, dist[i]);
    return max == Integer.MAX_VALUE ? -1 : max;
}

⏱️ Complexity

Time: O((V + E) log V). Heap operations take log V, done for V nodes and E edges.

Space: O(V + E). For the adjacency list and heap.

⚠️ Warning: Dijkstra FAILS if there are negative edge weights. Use Bellman-Ford instead.

Sub-Pattern 2: Bellman-Ford & Floyd-Warshall

💡 Core Concept

Bellman-Ford: Finds shortest paths from a single source, even with negative edge weights. It also detects negative cycles. Relaxes all edges V-1 times.
Floyd-Warshall: Finds shortest paths between ALL pairs of nodes. Uses O(V³) time and O(V²) space.

🧠 Step-by-Step Intuition: Bellman-Ford

  • Initialize dist[src] = 0, others to infinity.
  • Loop V - 1 times. In each iteration, go through all edges and relax them: if (dist[u] + w < dist[v]) dist[v] = dist[u] + w.
  • Negative Cycle Check: Run one more iteration. If any distance still updates, a negative cycle exists!

📝 Java Implementation: Bellman-Ford

public int[] bellmanFord(int n, int[][] edges, int src) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    
    // Relax V-1 times
    for (int i = 0; i < n - 1; i++) {
        for (int[] edge : edges) {
            int u = edge[0], v = edge[1], w = edge[2];
            if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
            }
        }
    }
    
    // Nth pass: Check for negative cycle
    for (int[] edge : edges) {
        int u = edge[0], v = edge[1], w = edge[2];
        if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v]) {
            return new int[]{-1}; // Negative cycle!
        }
    }
    return dist;
}

⏱️ Complexity

Bellman-Ford Time: O(V * E). V-1 passes over all edges.

Floyd-Warshall Time: O(V³). Triple nested loops over vertices.

Space: O(V) for BF, O(V²) for FW.

Sub-Pattern 3: Minimum Spanning Tree (Kruskal's)

💡 Core Concept

A Minimum Spanning Tree (MST) connects all vertices with the minimum possible total edge weight. Kruskal's algorithm is a greedy approach: sort all edges by weight, and add them to the MST if they don't create a cycle. It uses Union-Find (DSU) for cycle detection.

🧠 Step-by-Step Intuition

  • Sort all edges in ascending order of weight.
  • Initialize a Union-Find data structure for all N nodes.
  • Iterate through the sorted edges:
    • For edge (u, v), check if find(u) != find(v) (they are in different sets).
    • If yes, they don't form a cycle. Add to MST, and union(u, v).
    • If no, skip the edge (it would form a cycle).
  • Stop when the MST has exactly N - 1 edges.

class UnionFind {
    int[] parent, rank;
    public UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    public int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
    public boolean union(int x, int y) {
        int rootX = find(x), rootY = find(y);
        if (rootX == rootY) return false;
        if (rank[rootX] < rank[rootY]) parent[rootX] = rootY;
        else if (rank[rootX] > rank[rootY]) parent[rootY] = rootX;
        else { parent[rootY] = rootX; rank[rootX]++; }
        return true;
    }
}

public int kruskalMST(int n, int[][] edges) {
    Arrays.sort(edges, (a, b) -> a[2] - b[2]);
    UnionFind uf = new UnionFind(n);
    int cost = 0, edgesUsed = 0;
    
    for (int[] edge : edges) {
        if (uf.union(edge[0], edge[1])) {
            cost += edge[2];
            edgesUsed++;
            if (edgesUsed == n - 1) break;
        }
    }
    return edgesUsed == n - 1 ? cost : -1;
}

⏱️ Complexity

Time: O(E log E). Sorting edges dominates.

Space: O(V + E). For the Union-Find arrays.

Sub-Pattern 4: Minimum Spanning Tree (Prim's)

💡 Core Concept

Prim's algorithm builds the MST by starting from a single node and greedily growing the tree by adding the cheapest edge that connects a visited node to an unvisited node. It uses a Min-Heap (Priority Queue).

🧠 Step-by-Step Intuition

  • Initialize a Min-Heap with [0, startNode] (weight, node).
  • Maintain a visited boolean array.
  • While the heap is not empty and we haven't visited all nodes:
    • Pop the node with the smallest edge weight.
    • If already visited, skip.
    • Mark as visited. Add the weight to total cost.
    • Push all unvisited neighbors into the heap with their edge weights.

public int primMST(int n, List<List<int[]>> adj) {
    boolean[] visited = new boolean[n];
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    pq.offer(new int[]{0, 0}); // [weight, node]
    
    int cost = 0, nodesVisited = 0;
    
    while (!pq.isEmpty() && nodesVisited < n) {
        int[] curr = pq.poll();
        int w = curr[0], u = curr[1];
        
        if (visited[u]) continue;
        
        visited[u] = true;
        cost += w;
        nodesVisited++;
        
        for (int[] neighbor : adj.get(u)) {
            int v = neighbor[0], weight = neighbor[1];
            if (!visited[v]) {
                pq.offer(new int[]{weight, v});
            }
        }
    }
    return nodesVisited == n ? cost : -1;
}

⏱️ Complexity

Time: O(E log V). Similar to Dijkstra.

Space: O(V + E).

💡 Prim's vs Dijkstra: Dijkstra minimizes distance from the source. Prim's minimizes distance from the current MST.

Sub-Pattern 5: Bipartite Graph (2-Coloring)

💡 Core Concept

A graph is bipartite if its vertices can be divided into two independent sets such that every edge connects a vertex from one set to the other. Equivalently, it can be colored with 2 colors such that no two adjacent nodes have the same color. It contains no odd-length cycles.

🧠 Step-by-Step Intuition (BFS)

  • Initialize a color array with -1 (uncolored).
  • For each uncolored node, start BFS, color it with 0, and push to queue.
  • While queue is not empty:
    • Pop current node.
    • For each neighbor, if uncolored, color it with 1 - color[current] and push to queue.
    • If already colored, check if color[neighbor] == color[current]. If yes, it's not bipartite!

public boolean isBipartite(int[][] graph) {
    int n = graph.length;
    int[] color = new int[n];
    Arrays.fill(color, -1);
    
    for (int i = 0; i < n; i++) {
        if (color[i] != -1) continue;
        
        Queue<Integer> queue = new LinkedList<>();
        queue.offer(i);
        color[i] = 0;
        
        while (!queue.isEmpty()) {
            int u = queue.poll();
            for (int v : graph[u]) {
                if (color[v] == -1) {
                    color[v] = 1 - color[u];
                    queue.offer(v);
                } else if (color[v] == color[u]) {
                    return false; // Conflict
                }
            }
        }
    }
    return true;
}

Time: O(V + E). Standard BFS traversal.

Space: O(V). For the color array and queue.

Topological Sort

Sub-Pattern 1: Kahn's Algorithm (BFS / In-Degree)

💡 Core Concept

A topological sort is a linear ordering of vertices in a Directed Acyclic Graph (DAG) such that for every directed edge U -> V, vertex U comes before V. Kahn's algorithm uses BFS to repeatedly remove nodes with an in-degree of 0 (no incoming edges).

🧠 Step-by-Step Intuition

  • Compute the in-degree (number of incoming edges) for every node.
  • Initialize a Queue and add all nodes with in-degree == 0.
  • While the queue is not empty:
    • Pop the front node and add it to the topological order.
    • For each neighbor, decrement its in-degree by 1 (removing the edge).
    • If a neighbor's in-degree becomes 0, push it to the queue.
  • If the result list contains all `N` nodes, a valid topological sort exists. Otherwise, the graph has a cycle.

📝 Java Implementation

public int[] findOrder(int numCourses, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    int[] inDegree = new int[numCourses];
    
    for (int[] pre : prerequisites) {
        adj.get(pre[1]).add(pre[0]);
        inDegree[pre[0]]++;
    }
    
    Queue<Integer> queue = new LinkedList<>();
    for (int i = 0; i < numCourses; i++) {
        if (inDegree[i] == 0) queue.offer(i);
    }
    
    int[] order = new int[numCourses];
    int idx = 0;
    
    while (!queue.isEmpty()) {
        int curr = queue.poll();
        order[idx++] = curr;
        
        for (int neighbor : adj.get(curr)) {
            if (--inDegree[neighbor] == 0) {
                queue.offer(neighbor);
            }
        }
    }
    return idx == numCourses ? order : new int[0];
}

⏱️ Complexity

Time: O(V + E). We process each vertex and edge exactly once.

Space: O(V + E). For the adjacency list, in-degree array, and queue.

💡 Cycle Detection: If the final order array doesn't contain all nodes (i.e., `idx < numCourses`), the graph has a cycle. Return empty array.

Sub-Pattern 2: DFS Post-Order Traversal

💡 Core Concept

An alternative to Kahn's algorithm uses Depth-First Search. We explore a node's neighbors as deeply as possible. Once a node has no more unvisited neighbors, we add it to the front of a LinkedList (or push to a Stack). This is called a Post-Order Traversal.

🧠 Step-by-Step Intuition

  • Initialize a `visited` set and a `path` set (for cycle detection).
  • Iterate through all nodes. If a node is unvisited, call dfs(node).
  • In the DFS function:
    • If the node is in `path`, a cycle exists (return false).
    • Mark node as visited and add to `path`.
    • Recursively visit all neighbors.
    • Remove node from `path` (backtracking).
    • Add node to the front of the result list.

public int[] findOrderDFS(int numCourses, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    for (int[] pre : prerequisites) adj.get(pre[1]).add(pre[0]);
    
    boolean[] visited = new boolean[numCourses];
    boolean[] path = new boolean[numCourses];
    LinkedList<Integer> result = new LinkedList<>();
    
    for (int i = 0; i < numCourses; i++) {
        if (!visited[i]) {
            if (!dfs(i, adj, visited, path, result)) return new int[0]; // Cycle
        }
    }
    return result.stream().mapToInt(i -> i).toArray();
}

private boolean dfs(int node, List<List<Integer>> adj, boolean[] visited, 
                    boolean[] path, LinkedList<Integer> result) {
    if (path[node]) return false; // Cycle detected
    if (visited[node]) return true;
    
    path[node] = true;
    for (int neighbor : adj.get(node)) {
        if (!dfs(neighbor, adj, visited, path, result)) return false;
    }
    
    path[node] = false; // Backtrack
    visited[node] = true;
    result.addFirst(node); // Add to front (post-order)
    return true;
}

⏱️ Complexity

Time: O(V + E). Every node and edge is visited once.

Space: O(V + E). The recursion stack can go up to O(V) deep.

Sub-Pattern 3: Cycle Detection (Course Schedule)

💡 Core Concept

Topological sort is only possible on a Directed Acyclic Graph (DAG). If the graph has a cycle, we cannot finish all tasks. Both Kahn's Algorithm and DFS can be modified to detect cycles.

🧠 Step-by-Step Intuition (Kahn's)

  • Run standard Kahn's algorithm (BFS with in-degree).
  • Keep a counter of how many nodes have been processed.
  • If the counter equals N at the end, there is no cycle.
  • If the counter is less than N, it means some nodes are stuck in a cycle and their in-degree never reached 0. Cycle detected!

public boolean canFinish(int numCourses, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    int[] inDegree = new int[numCourses];
    
    for (int[] pre : prerequisites) {
        adj.get(pre[1]).add(pre[0]);
        inDegree[pre[0]]++;
    }
    
    Queue<Integer> queue = new LinkedList<>();
    for (int i = 0; i < numCourses; i++) {
        if (inDegree[i] == 0) queue.offer(i);
    }
    
    int count = 0;
    while (!queue.isEmpty()) {
        int curr = queue.poll();
        count++;
        
        for (int neighbor : adj.get(curr)) {
            if (--inDegree[neighbor] == 0) {
                queue.offer(neighbor);
            }
        }
    }
    
    // If we couldn't process all courses, there's a cycle
    return count == numCourses;
}

⏱️ Complexity

Time: O(V + E). Standard BFS traversal.

Space: O(V + E). For the adjacency list and queue.

Sub-Pattern 4: Lexicographical Order (Alien Dictionary)

💡 Core Concept

Sometimes we need the topological order that is smallest in lexicographical order. We can achieve this by replacing the standard FIFO Queue in Kahn's Algorithm with a Min-Heap (Priority Queue).

🧠 Step-by-Step Intuition

  • Build the graph (adjacency list) and compute the in-degrees.
  • Initialize a PriorityQueue (Min-Heap) and add all nodes with 0 in-degree.
  • While the heap is not empty:
    • Poll the smallest character (alphabetically) from the heap.
    • Append it to the result.
    • Decrement in-degrees of neighbors, and push any that become 0 into the heap.

public String alienOrder(String[] words) {
    Map<Character, Set<Character>> adj = new HashMap<>();
    int[] inDegree = new int[26];
    int uniqueChars = 0;
    
    // Initialize graph
    for (String w : words) {
        for (char c : w.toCharArray()) {
            if (inDegree[c - 'a'] == 0) uniqueChars++;
            inDegree[c - 'a']++; // Temporarily count for init
        }
    }
    
    // Build edges
    for (int i = 0; i < words.length - 1; i++) {
        String w1 = words[i], w2 = words[i + 1];
        int minLen = Math.min(w1.length(), w2.length());
        for (int j = 0; j < minLen; j++) {
            if (w1.charAt(j) != w2.charAt(j)) {
                adj.computeIfAbsent(w1.charAt(j), k -> new HashSet<>()).add(w2.charAt(j));
                break;
            }
        }
    }
    
    // Reset in-degrees properly
    Arrays.fill(inDegree, 0);
    for (Set<Character> neighbors : adj.values()) {
        for (char c : neighbors) inDegree[c - 'a']++;
    }
    
    // Min-Heap Topological Sort
    PriorityQueue<Character> pq = new PriorityQueue<>();
    for (int i = 0; i < 26; i++) {
        if (inDegree[i] == 0 && adj.containsKey((char)(i + 'a'))) {
            pq.offer((char)(i + 'a'));
        }
    }
    
    StringBuilder sb = new StringBuilder();
    while (!pq.isEmpty()) {
        char c = pq.poll();
        sb.append(c);
        if (adj.containsKey(c)) {
            for (char next : adj.get(c)) {
                if (--inDegree[next - 'a'] == 0) pq.offer(next);
            }
        }
    }
    
    return sb.length() == uniqueChars ? sb.toString() : "";
}

⏱️ Complexity

Time: O(C + E log V). Where C is total characters in words, E is edges. Heap operations take log V.

Space: O(V + E).

Union Find

Sub-Pattern 1: Disjoint Set Union (Core Concept)

💡 Core Concept

Union Find (or DSU) is a data structure that keeps track of a set of elements partitioned into a number of disjoint (non-overlapping) subsets. It provides two primary operations:
Find(x): Determine which subset an element belongs to (returns the representative/root).
Union(x, y): Merge two subsets into a single subset.

🧠 Step-by-Step Intuition

  • We represent the data structure using an array parent[] where parent[i] points to the parent of node `i`.
  • Initially, every element is its own set: parent[i] = i.
  • Find: Follow the parent pointers until you reach a node that points to itself (the root).
  • Union: Find the roots of both elements. If they are different, point one root to the other.

class UnionFind {
    int[] parent;
    
    public UnionFind(int n) {
        parent = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i;
        }
    }
    
    public int find(int x) {
        while (parent[x] != x) {
            x = parent[x];
        }
        return x;
    }
    
    public void union(int x, int y) {
        int rootX = find(x);
        int rootY = find(y);
        if (rootX != rootY) {
            parent[rootX] = rootY;
        }
    }
}

Time: O(N) for `find` in the worst case (skewed tree). O(N) for `union`.

Space: O(N) for the parent array.

⚠️ Problem: If we always attach rootX to rootY, the tree can become a straight line (linked list), making `find` extremely slow. We need optimization!

Sub-Pattern 2: Path Compression & Union by Rank

💡 Core Concept

To achieve near O(1) time complexity (O(α(N))), we use two critical optimizations:
1. Path Compression (in Find): Flatten the tree by making every node point directly to the root during `find`.
2. Union by Rank/Size (in Union): Always attach the smaller/shallower tree to the root of the larger/deeper tree.

🧠 Step-by-Step Intuition

  • Path Compression: parent[x] = find(parent[x]). This recursively updates all nodes along the path to point directly to the root.
  • Union by Rank: Maintain a rank[] array. When merging, compare ranks. Attach the lower rank tree to the higher rank tree. If ranks are equal, increment the rank of the new root.
  • Union by Size: Same as rank, but store the number of nodes in the tree. Attach the smaller set to the larger set.

📝 Java Implementation (Optimized)

class UnionFind {
    int[] parent;
    int[] rank;
    
    public UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    
    // Path Compression
    public int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]); // Flatten
        }
        return parent[x];
    }
    
    // Union by Rank
    public boolean union(int x, int y) {
        int rootX = find(x), rootY = find(y);
        if (rootX == rootY) return false;
        
        if (rank[rootX] < rank[rootY]) {
            parent[rootX] = rootY;
        } else if (rank[rootX] > rank[rootY]) {
            parent[rootY] = rootX;
        } else {
            parent[rootY] = rootX;
            rank[rootX]++;
        }
        return true;
    }
}

⏱️ Complexity

Time: O(α(N)) per operation. α is the Inverse Ackermann function, which is effectively O(1).

Space: O(N). For `parent` and `rank` arrays.

💡 Note: If you use Union by Size, replace `rank` with `size` and initialize all values to 1. Update `size[root] += size[child]` when merging.

Sub-Pattern 4: Cycle Detection (Redundant Connection)

💡 Core Concept

In an undirected graph, a cycle is formed if we try to add an edge between two nodes that are already in the same connected component. Union Find naturally detects this: if find(u) == find(v), adding the edge (u, v) creates a cycle.

🧠 Step-by-Step Intuition

  • Initialize UnionFind.
  • Iterate through the edges one by one.
  • For edge (u, v):
  • If find(u) == find(v), they are already connected. Adding this edge creates a cycle! Return this edge.
  • Otherwise, merge them: union(u, v).

📝 Java Implementation

public int[] findRedundantConnection(int[][] edges) {
    int n = edges.length;
    // Nodes are 1-indexed in this problem, so size n+1
    UnionFind uf = new UnionFind(n + 1);
    
    for (int[] edge : edges) {
        int u = edge[0], v = edge[1];
        
        // If they are already connected, this edge forms a cycle
        if (!uf.union(u, v)) {
            return edge;
        }
    }
    return new int[0];
}

Sub-Pattern 5: Union Find on a Grid (Number of Islands II)

💡 Core Concept

If a grid is static, BFS/DFS is usually better. But if islands are being added one by one dynamically, Union Find shines. We can map 2D coordinates `(row, col)` to a 1D index: index = row * cols + col.

🧠 Step-by-Step Intuition

  • Initialize a DSU of size rows * cols. Set all `parent[i] = -1` to indicate water.
  • Maintain an `islandCount` variable.
  • For each newly added land position `(r, c)`:
    • Convert to 1D index. Set `parent[idx] = idx`. Increment `islandCount`.
    • Check all 4 neighbors. If a neighbor is land (parent != -1), try to `union(idx, neighborIdx)`.
    • If union succeeds (they were separate), `islandCount--`.
  • Record `islandCount` after each addition.

📝 Java Implementation

public List<Integer> numIslands2(int m, int n, int[][] positions) {
    List<Integer> res = new ArrayList<>();
    int[] parent = new int[m * n];
    Arrays.fill(parent, -1); // -1 means water
    int count = 0;
    int[][] dirs = {{0,1},{1,0},{0,-1},{-1,0}};
    
    for (int[] pos : positions) {
        int r = pos[0], c = pos[1];
        int idx = r * n + c;
        
        if (parent[idx] != -1) { // Duplicate position
            res.add(count); continue;
        }
        
        parent[idx] = idx;
        count++;
        
        for (int[] d : dirs) {
            int nr = r + d[0], nc = c + d[1];
            if (nr >= 0 && nr < m && nc >= 0 && nc < n) {
                int nIdx = nr * n + nc;
                if (parent[nIdx] != -1) {
                    if (union(parent, idx, nIdx)) count--;
                }
            }
        }
        res.add(count);
    }
    return res;
}

// Standalone Union function with Path Compression
private boolean union(int[] parent, int i, int j) {
    int rootI = find(parent, i), rootJ = find(parent, j);
    if (rootI != rootJ) {
        parent[rootI] = rootJ;
        return true;
    }
    return false;
}
private int find(int[] parent, int i) {
    if (parent[i] != i) parent[i] = find(parent, parent[i]);
    return parent[i];
}

⏱️ Complexity

Time: O(K * α(M*N)). Where K is the number of positions added.

Space: O(M * N) for the parent array.

⚠️ Common Mistakes

1. Forgetting Path Compression

Without path compression, the tree can become a linked list, degrading `find` to O(N). Always use parent[x] = find(parent[x]).

2. Using Union Find on Directed Graphs

DSU only tracks connectivity, not direction. If A points to B, DSU treats it the same as B pointing to A. Do not use DSU for dependency resolution (use Topological Sort instead).

3. Not Using Union by Rank

If you don't attach the smaller tree to the larger tree, path compression alone is not enough to guarantee O(α(N)) amortized time in all cases.

4. 1D Index Mapping Errors

For grid problems, ensure the mapping `index = r * cols + c` is correct. If the grid is 1-indexed, map it to 0-indexed first.

Sub-Pattern 1: Basic Trie & Node Structure

💡 Core Concept

A Trie is a tree-like data structure used to efficiently store and retrieve strings in a dataset. It is highly effective for prefix matching and autocomplete features. Unlike a binary search tree, no node stores the key; instead, the position in the tree defines the key.

🧠 Step-by-Step Intuition

  • TrieNode: Each node contains an array of child pointers (usually size 26 for lowercase English letters) and a boolean isEnd flag.
  • Insert: Traverse the string character by character. If a child node for the current character doesn't exist, create it. Move to the child. At the end of the word, set isEnd = true.
  • Search: Traverse the string. If a child doesn't exist, return false. If we reach the end, return node.isEnd.
  • StartsWith: Similar to search, but we only care if we can traverse the entire prefix. No need to check isEnd.

class TrieNode {
    TrieNode[] children = new TrieNode[26];
    boolean isEnd;
}

class Trie {
    private TrieNode root;
    
    public Trie() {
        root = new TrieNode();
    }
    
    public void insert(String word) {
        TrieNode node = root;
        for (char c : word.toCharArray()) {
            int idx = c - 'a';
            if (node.children[idx] == null) {
                node.children[idx] = new TrieNode();
            }
            node = node.children[idx];
        }
        node.isEnd = true;
    }
}

⏱️ Complexity

Time: O(L). Where L is the length of the word. We traverse L nodes.

Space: O(N * L * 26). Worst case, N words of length L, each node holds a 26-size array.

💡 Core Concept

Sub-Pattern 3: Wildcard Search (Trie + DFS)

💡 Core Concept

When the search query contains a wildcard '.' (which matches any single character), we cannot simply traverse one path. Instead, we must use DFS (Backtracking) to explore all child branches when a '.' is encountered.

🧠 Step-by-Step Intuition

  • Create a DFS function searchInNode(word, index, node).
  • If index == word.length(), return node.isEnd.
  • Let c = word[index].
  • If c == '.': loop through all 26 children. If a child is not null and searchInNode(word, index+1, child) returns true, return true.
  • If c != '.': traverse to the specific child and recurse.

👀 Visual Dry Run

Words: ["bad", "dad", "mad"], Search: ".ad"

Index 0 ('.'):
Loop children 'b', 'd', 'm'.
Branch 'b':
Index 1 is 'a'. Traverse 'a' -> 'd'. isEnd=true. Found "bad"! Return true.

📝 Java Implementation

public boolean search(String word) {
    return dfs(word, 0, root);
}

private boolean dfs(String word, int idx, TrieNode node) {
    if (idx == word.length()) return node.isEnd;
    char c = word.charAt(idx);
    
    if (c != '.') {
        TrieNode next = node.children[c - 'a'];
        return next != null && dfs(word, idx + 1, next);
    }
    
    // Wildcard: check all possible branches
    for (int i = 0; i < 26; i++) {
        if (node.children[i] != null) {
            if (dfs(word, idx + 1, node.children[i])) {
                return true;
            }
        }
    }
    return false;
}

⏱️ Complexity

Time: O(26^L) worst case. If all characters are '.', we branch 26 ways.

Space: O(L). Recursion stack depth.

Sub-Pattern 4: Word Search II (Trie + Matrix DFS)

💡 Core Concept

Given a 2D grid and a list of words, find all words that can be formed by adjacent cells. We build a Trie from the word list, then DFS from each cell in the grid. The Trie allows us to prune the DFS immediately if the current path doesn't form a valid prefix.

🧠 Step-by-Step Intuition

  • Build a Trie from all words. Store the actual word at the terminal node (`String word`) for easy retrieval.
  • Iterate through every cell in the grid.
  • If the cell's character exists in the Trie root's children, start DFS.
  • In DFS, mark the cell visited (e.g., `#`). Move to the Trie child node. Check the 4 neighbors.
  • If the Trie node has a `word`, add it to the result and set it to null (to avoid duplicates).
  • Backtrack: Restore the original character before returning.

👀 Visual Dry Run

Board: [["o","a"],["e","t"]], Words: ["eat","oat"]

'o'. Root has child 'o'. Mark '#'.
DFS (1,0):
'e'. Child 'e' exists? No. Backtrack.
DFS (0,1):
'a'. Child 'a' exists? Yes. Recurse.

📝 Java Implementation

class TrieNode {
    TrieNode[] children = new TrieNode[26];
    String word;
}

public List<String> findWords(char[][] board, String[] words) {
    TrieNode root = new TrieNode();
    for (String w : words) {
        TrieNode node = root;
        for (char c : w.toCharArray()) {
            if (node.children[c-'a'] == null) node.children[c-'a'] = new TrieNode();
            node = node.children[c-'a'];
        }
        node.word = w;
    }
    
    List<String> res = new ArrayList<>();
    for (int i = 0; i < board.length; i++) {
        for (int j = 0; j < board[0].length; j++) {
            dfs(board, i, j, root, res);
        }
    }
    return res;
}

private void dfs(char[][] board, int r, int c, TrieNode node, List<String> res) {
    if (r < 0 || r >= board.length || c < 0 || c >= board[0].length) return;
    char ch = board[r][c];
    if (ch == '#' || node.children[ch-'a'] == null) return;
    
    node = node.children[ch-'a'];
    if (node.word != null) {
        res.add(node.word);
        node.word = null; // Prevent duplicates
    }
    
    board[r][c] = '#'; // Mark visited
    dfs(board, r+1, c, node, res);
    dfs(board, r-1, c, node, res);
    dfs(board, r, c+1, node, res);
    dfs(board, r, c-1, node, res);
    board[r][c] = ch; // Backtrack
}

⏱️ Complexity

Time: O(M * N * 4^L). Where L is the max word length. Trie pruning reduces this significantly.

Space: O(Total characters in words) for the Trie.

Sub-Pattern 5: Advanced Variations

💡 Core Concept

Tries can be adapted for complex scenarios requiring optimized memory or different character sets.

🧠 Step-by-Step Intuition

  • Map-based Trie: Instead of a fixed 26-size array, use a HashMap<Character, TrieNode>. This saves memory if the alphabet is large (e.g., Unicode) or sparse, but slightly slower due to hashing overhead.
  • Compressed Trie (Radix Tree): Merge nodes with only one child into a single node containing a string. This drastically reduces memory usage for long words with unique suffixes.
  • Maximum XOR of Two Numbers: Store numbers in a Trie where each node has 2 children (0 and 1), traversing from the most significant bit. To find the max XOR, greedily pick the opposite bit at each level.

class TrieNode {
    TrieNode[] children = new TrieNode[2];
}

public int findMaximumXOR(int[] nums) {
    TrieNode root = new TrieNode();
    int max = 0;
    
    // Build Trie
    for (int num : nums) {
        TrieNode node = root;
        for (int i = 31; i >= 0; i--) {
            int bit = (num >> i) & 1;
            if (node.children[bit] == null) {
                node.children[bit] = new TrieNode();
            }
            node = node.children[bit];
        }
    }
    
    // Find max XOR
    for (int num : nums) {
        TrieNode node = root;
        int currXOR = 0;
        for (int i = 31; i >= 0; i--) {
            int bit = (num >> i) & 1;
            int opp = 1 - bit;
            
            if (node.children[opp] != null) {
                currXOR |= (1 << i);
                node = node.children[opp];
            } else {
                node = node.children[bit];
            }
        }
        max = Math.max(max, currXOR);
    }
    return max;
}

⏱️ Complexity

Time: O(N * 32). N numbers, 32 bits each.

Space: O(N * 32) for the Trie.

Dynamic Programming & Greedy

💡 Core Intuition

If a problem asks for "Max/Min", "Number of ways", or "Longest/Shortest" and has overlapping subproblems, it's DP. Define the State, Transition, and Base Case before writing code.

📝 The 5 Core DP Templates

1. 1D DP (Fibonacci / Stairs)

int[] dp = new int[n + 1];
dp[0] = 1; dp[1] = 1;
for (int i = 2; i <= n; i++)
    dp[i] = dp[i-1] + dp[i-2];

2. 0/1 Knapsack (Include/Exclude)

for (int i = 1; i <= n; i++) {
  for (int w = 1; w <= W; w++) {
    if (wt[i] <= w)
      dp[i][w] = max(val[i] + dp[i-1][w-wt[i]], dp[i-1][w]);
    else dp[i][w] = dp[i-1][w];
  }
}

3. Unbounded Knapsack (Coin Change)

// Iterate forward to allow reuse
for (int i = 0; i < coins.length; i++) {
  for (int w = coins[i]; w <= W; w++) {
    dp[w] = min(dp[w], dp[w - coins[i]] + 1);
  }
}

4. LIS (Longest Increasing Subseq)

for (int i = 1; i < n; i++) {
  for (int j = 0; j < i; j++) {
    if (nums[i] > nums[j])
      dp[i] = max(dp[i], dp[j] + 1);
  }
}

⚡ Tricks & Techniques

Space Optimization

If dp[i] only depends on dp[i-1] (or dp[i-1] and dp[i-2]), you can replace the 2D array with a 1D array or just two variables.

String DP (LCS)

For two strings, use a 2D array. If characters match: dp[i][j] = dp[i-1][j-1] + 1. Else, max(dp[i-1][j], dp[i][j-1]).

  • Negative Numbers: Does Sliding Window fail? (Use Prefix Sum).
  • Overflow: Use `long` if values can exceed `Integer.MAX_VALUE` (2^31-1).
  • Cycles: Graph/Tree problems. Do you have a `visited` set?

🌳 Which Pattern Should I Use?

Follow this decision tree to quickly identify the correct algorithmic pattern based on the problem description.

Is it an Array or String?
│
├── Sorted?
│   └── Two Pointers or Binary Search
│
├── Subarray or Substring?
│   ├── Positive numbers? ──> Sliding Window
│   └── Negative numbers? ──> Prefix Sum + Hash Map
│
├── Range Sum Query? ──> Prefix Sum
│
└── Pairs / Triplets? ──> Two Pointers (if sorted) or Hash Map


Is it a Graph or Tree?
│
├── Shortest Path?
│   ├── Unweighted? ──> BFS
│   └── Weighted? ──> Dijkstra (no neg) or Bellman-Ford (neg)
│
├── Connectivity? ──> Union Find or DFS
│
├── Dependencies / Order? ──> Topological Sort
│
└── Maximum/Minimum Cost? ──> Kruskal's or Prim's (MST)


Is it a Decision / Optimization Problem?
│
├── Local choice is always best? ──> Greedy
│
├── Overlapping Subproblems? ──> Dynamic Programming
│   ├── Sequence (1D)? ──> 1D DP (Fibonacci, House Robber)
│   ├── Grid or 2 Strings (2D)? ──> 2D DP (LCS, Edit Distance)
│   └── Choices with Capacity? ──> Knapsack
│
└── Find ALL combinations? ──> Backtracking
